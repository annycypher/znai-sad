# Изображения «Сад знаний»: размеры, вес, формат

Правило сайта: **ни одного изображения тяжелее 200 KB** и ни одного «просто залитого с телефона» файла.
Считаем по формуле: нужная ширина на экране × 2 (для экранов Retina) × запас на кроп.

## 2. Жёсткие правила (без исключений)

1. **Формат по умолчанию — WebP.** JPEG оставляем только для `og:image` и старых файлов; PNG — для иконок, схем и прозрачности. AVIF не используем, пока не настроен fallback: часть телефонов его не показывает.
2. **2x для всего, что показывается крупно.** Hero, карточки, галереи растений, обложки: делаем двойной размер, браузер сам выберет нужный через `srcset`.
3. **Атрибуты `width` и `height` обязательны** — без них верстка «прыгает» при загрузке (страдает оценка удобства и позиции).
4. **`loading="lazy"` — всем, кроме hero и первого изображения статьи.** Логотип и hero грузятся сразу.
5. **Alt у каждого изображения** — короткое описание по делу: «гортензия метельчатая в середине лета», а не «фото 1.jpg».
6. **Имя файла — транслитом, со смыслом:** `gortenziya-metelchataya-cvetenie.webp`. Имя файла работает на SEO и порядок в медиатеке.
7. **Не масштабируем вверх.** Если исходник 600 px, из него не может получиться карточка 1200 px — получится мыло.
8. **Кроп — только осмысленный:** главный объект в центре, отступ 10–15 % по краям, чтобы не резалось при 3:2 и 1:1.

## 3. Размеры WordPress (что регистрируем в теме)

Чтобы не грузить на страницу картинку 4000 px, регистрируем свои размеры и указываем их в шаблонах:

| Имя размера | Ширина × высота | Кроп | Где используется |
|---|---|---|---|
| `sz-hero` | 1600×900 | да | Hero главной и посадочных |
| `sz-cover` | 800×450 | да | Списки статей, рубрики |
| `sz-card` | 600×400 | да | Плитки, баннеры |
| `sz-plant` | 600×600 | да | Карточки растений |
| `sz-gallery` | 1200×900 | да | Галерея в карточке растения |
| `sz-thumb` | 400×400 | да | Календарь, миниатюры работ |
| `sz-og` | 1200×630 | да | Превью для соцсетей |

Правило загрузки: в медиатеку заливаем исходник **не больше 2400 px по длинной стороне** — WordPress сам сделает 800×450, 600×400 и остальное. Оригиналы больше 2400 px не нужны: они весят как 5 картинок, а в интерфейсе не используются.

## 4. Чем сжимать

| Формат | Инструмент | Настройка |
|---|---|---|
| WebP из JPEG/PNG | Squoosh (веб) или `cwebp` | качество 75–80, для фото 78 |
| JPEG для og:image | Squoosh, Photoshop «Сохранить для Web» | качество 80–85, прогрессивный |
| PNG (иконки, схемы) | TinyPNG, `pngquant` | 256 цветов, без потерь по краям |
| SVG | SVGO, обрезка в Figma/Illustrator | убрать метаданные, объединить пути |

## 5. Проверка перед публикацией

- [ ] Вес файла ≤ нормы из таблицы раздела 1.
- [ ] Ширина не меньше, чем нужно для 2x отображения.
- [ ] `width`/`height` заданы, `alt` заполнен, имя файла транслитом.
- [ ] Для героя — без `lazy`, для остального — с `lazy`.
- [ ] Общая страница: картинок не более 12–15, суммарный вес изображений ≤ 1,5 МБ.
- [ ] Проверка через PageSpeed Insights: показатель LCP ≤ 2,5 с, CLS ≤ 0,1.

## 6. Текущее состояние сайта

На сегодня в теме используются **локальные SVG-иконки и встроенные схемы** (ноль внешних запросов) плюс фото-заглушки в `assets/img/`. Когда появятся реальные фото:
1. заливаем исходники ≤ 2400 px в медиатеку;
2. регистрируем размеры из раздела 3 в `includes/assets.php`;
3. в шаблонах выводим `the_post_thumbnail( 'sz-card' )` с `loading="lazy"`;
4. для `og:image` в `includes/seo.php` ставим размер `sz-og`.
