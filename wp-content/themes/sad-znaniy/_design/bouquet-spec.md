## 1. CPT `flower` (справочник цветов)

Новый тип записи **`flower`**, не `plant`: у цветка есть значение, а не агротехника.
Регистрация — по образцу `sad_znaniy_register_plant()`.

| Параметр | Значение |
|---|---|
| `labels` | Цветы и значения / Цветок / Добавить цветок … |
| `public` | `true` (значения публичны — это контент страниц) |
| `show_in_rest` | `true` |
| `has_archive` | `false` в MVP (архив не нужен, чтобы не плодить пустышки) |
| `rewrite.slug` | `tsvety-znachenie`, `with_front => false` |
| `supports` | `title`, `editor`, `thumbnail`, `excerpt`, `page-attributes` |
| `menu_icon` | `dashicons-heart` |
| `menu_position` | 23 (рядом с «Растениями») |

### 1.1 Метаполя

| Ключ | Тип | Смысл | Санитизация |
|---|---|---|---|
| `_sz_fl_meaning` | string | значимость, 1–2 слова | `sanitize_text_field` |
| `_sz_fl_desc` | text | описание, 2–3 предложения | `sanitize_textarea_field` |
| `_sz_fl_category` | key | `love/friendship/respect/new/memory/filler` | белый список |
| `_sz_fl_rare` | `1`/`''` | редкость (бейдж ✦) | `sanitize_key` |
| `_sz_fl_season` | string | месяцы цветения `03,04,05` (опц.) | только цифры и запятые |
| `_sz_fl_plant` | int | ID карточки `plant` либо `0` | `absint` |
| `_sz_fl_bad` | string | slugs конфликтных цветов через запятую | `sanitize_key` по списку |
| `_sz_fl_warn` | string | мягкие предупреждения (текст) | `sanitize_textarea_field` |
| `_sz_fl_photo` | string | путь к фото из «Фото-скана» | `esc_url_raw`/относительный путь |
| `_sz_fl_alias` | string | алиасы через запятую (лютик→ранункулюс) | `sanitize_text_field` |
| `_sz_fl_variant_of` | string | slug базового цветка для цветовых вариантов | `sanitize_title` |
| `_sz_fl_genitive` | string | родительный падеж для названий («розы») | `sanitize_text_field` |
| `_sz_fl_desc_fp` | `1`/`''` | метка «факт-проверка не пройдена» (видна в админке) | `sanitize_key` |
| `_sz_fl_sort` | int | порядок в справочнике | `absint` |

Категории — один словарь на проект: `sad_znaniy_flower_categories()`.

### 1.2 Админка (трио)

- Метабокс «Значение цветка»: значимость, описание, категория, редкость, сезон, связь с растением
  (выпадающий список опубликованных `plant`), конфликты (`bad`), алиасы, вариант.
- Метабокс «Фото»: превью миниатюры/файла и кнопка «Найти в папке» (см. §1б).
- Сохранение: nonce `sad_znaniy_flower_save`, `current_user_can( 'edit_post' )`,
  белые списки, `sanitize_*` на вход (стандарт 7.3).
- Колонки списка: категория, редкость, сезон, связь с растением, фото (есть/нет).
- Публикация записей — **только по команде владельца**; нейронка готовит контент,
  владелец вычитывает ФП-метки и публикует (правило проекта).

### 1.3 Установка (Партия 1)

`includes/cpt-flower.php` + `sad_znaniy_maybe_install_flowers()` на `wp_loaded`:
проверка `get_option( 'sad_znaniy_flowers_ready' )`, создание записей по словарю §2
со статусом `publish` (решение владельца: значения публичны — это и есть контент страниц),
метка **ФП** — в `_sz_fl_desc_fp` до вычитки; `flush_rewrite_rules()` один раз, флаг в опции.
Повторный запуск ничего не дублирует
(проверка по `get_page_by_path( $slug, OBJECT, 'flower' )`).

## 1б. Фото-конвейер

Приоритет вывода фото в кружке:

1. `_sz_fl_photo` — путь, привязанный через «Фото-скан»;
2. миниатюра записи `flower` (`the_post_thumbnail`), если загружена в админке;
3. fallback — стеклянный круг с первой буквой названия.

Фото **не обрезается в файле**: круг делается выводом — `border-radius:50%`, `object-fit:cover`,
стеклянное кольцо `box-shadow: inset 0 0 0 3px rgba(255,255,255,.85)`.

### Экран «Фото-скан» (в меню CPT, Партия 1)

- Сканирует `assets/img/flowers/` (`jpg/jpeg/png/webp`), выводит таблицу:
  «цветок / найденный файл / статус / кнопка привязать».
- Матчинг: имя записи → транслитерация (`sad_znaniy_translit()`), регистронезависимо,
  по первому слову названия («Гортензия метельчатая» → `gortenziya`).
  Поддерживаются русские имена файлов («Роза.jpg») и латиница (`roza.jpg`).
- Привязка пишет относительный путь в `_sz_fl_photo`; файл не копируется.
- Если совпадений несколько — ручной выбор из списка. Экран доступен только `manage_options`.

## 3. Матрица «повод × кому» → веса категорий (11×6)

### 3.1 Ключи

**Поводы (11):** `birthday` (день рождения), `wedding` (свадьба/годовщина), `march8` (8 марта),
`teacher_day` (День учителя/1 сентября), `love` (признание в любви), `thanks` (спасибо),
`jubilee` (юбилей), `housewarming` (новоселье), `baby` (рождение ребёнка),
`condolence` (соболезнования/память), `just_because` (просто так).

**Кому (6):** `mama` (маме/бабушке), `beloved` (любимой), `friend` (подруге),
`colleague` (коллеге), `teacher` (учителю/воспитателю), `man` (мужчине: папа/друг/руководитель).

Веса по категориям: `L` любовь, `D` дружба, `U` уважение, `N` новое, `P` память. Шкала 0–5.

| Кому | ΔL | ΔD | ΔU | ΔN | ΔP | Смысл |
|---|---|---|---|---|---|---|
| `mama` | +1 | 0 | +1 | +1 | 0 | нежность через уважение |
| `beloved` | +2 | 0 | −1 | 0 | 0 | усилить любовь |
| `friend` | 0 | +2 | −1 | 0 | 0 | дружба |
| `colleague` | −3 | +1 | +2 | 0 | 0 | любовь неуместна |
| `teacher` | −3 | −1 | +2 | 0 | 0 | только уважение |
| `man` | −2 | +1 | +1 | 0 | 0 | сдержанно |

Итог: `score(category) = clamp(base[occasion][category] + modifier[to][category], 0, 5)`.
Матрица 11×6 хранится в БД как готовые векторы (сложение выполняется один раз при установке),
чтобы движок не считал на лету.

### 3.5 Алгоритм ранжирования (движок)

1. Берём вектор ячейки `occasion × to`.
2. Для цветка: `primary` — максимальный вес среди его категорий, `secondary` — второй по величине.
   `score = primary × 2 + secondary`. Зелень (`filler`) в подборе не участвует по умолчанию.
3. **Жёсткий конфликт** (`hard`) убирает цветок из блока «Рекомендуемые», но оставляет в общем
   списке с красной плашкой. **Мягкий** (`soft`) — `score − 4`.
4. Редкость (✦) и сезонность — **только бейджи**, на балл не влияют.
5. Варианты (`_sz_fl_variant_of`) в сетке не дублируются; базовый цветок представляет группу.
6. Порядок при равенстве: `_sz_fl_sort` asc, затем название.
7. Рекомендуемые — первые **8**; ниже — все остальные с фильтром по категории.

### 3.6 Контрольные примеры (приёмка движка, Партия 1)

| Запрос | Ожидание |
|---|---|
| `love` + `beloved` | первыми идут розы (красная/розовая) и тюльпаны — категория `L` доминирует |
| `thanks` + `mama` | гербера, розовая роза, гортензия, хризантема — «дружба/уважение», без конфликтов |
| `teacher_day` + `teacher` | гладиолус, ирис, хризантема, хоста — `U` доминирует, красные розы не в топе |
| `condolence` + `mama` | хризантема, гвоздика, лилия белая, астра — `P` доминирует |
| ландыш + красная роза | красная плашка «Ландыш не сочетается с розами» |
| один тюльпан | режим «Солитёр» + манифест |

## 4. Нечётность и режим «Солитёр»

Считаем **стебли**, а не виды: `count = Σ items[].count` (повторный клик по кружку +1,
кнопки «−/+» в композиции).

| Стеблей | Состояние | Подсказка |
|---|---|---|
| 0 | пусто | «Выберите цветы — начнём с трёх» |
| 1 | **Солитёр** | манифест (ниже) |
| 2 | чётное | «Два цветка легко теряются. Добавьте третий — нечётное число выглядит живым» |
| 3–9 | норма | «Хороший букет: N стеблей» (зелёная плашка) |
| 10–25 | крупный | «Крупный букет: проверьте, хватит ли зелени и упаковки» |
| > 25 | лимит | «Больше 25 — это уже корзина; уменьшите количество» |

Нечётность — **подсказка**, не блокировка: сохранить можно любой букет.

### Манифест солитёра (текст на утверждение)

> «Один цветок — это не „мало“. Это знак, который не нужно усиливать: тебя выбрали из всех.
> {Название} говорит за вас, когда слов слишком много или слишком мало.
> Такой букет уместен, когда важна не пышность, а точность чувства.»

В режиме солитёра: кружок укрупняется (112 px), включается соло-анимация (§9),
скрываются счётчик чётности и подсказка «добавьте ещё». Название генерируется
по шаблону «Соло {цветок}» / «Один {цветок}» (перегенерация доступна).

## 5. Словарь конфликтов

Три типа правил: **пара** (`a` + `b` в букете), **повод** (цветок + occasion),
**доля** (группа цветов занимает больше N % стеблей). Тип `hard` — красная плашка
и исключение из «Рекомендуемых»; `soft` — жёлтая плашка и `score − 4`.

### 5.1 Базовые 6 правил (из ТЗ)

| ID | Тип | Условие | Плашка |
|---|---|---|---|
| `landysh-ethylene` | hard | Ландыш + любая роза / тюльпан / нарцисс | «Ландыш не стоит в одном букете с розами, тюльпанами и нарциссами — он быстро вянет и токсичен для соседей» |
| `gvozdika-etiquette` | hard | Гвоздика + поводы `love`, `wedding`, `march8` | «В России гвоздика ассоциируется с памятью и 9 Мая — для романтики и 8 Марта лучше другой цветок» |
| `condolence-bright` | hard | `condolence` + подсолнух / гербера / красный тюльпан / пион / орхидея | «Для соболезнований выбирают сдержанные тона: белые, кремовые, бордовые» |
| `yellow-separation` | soft | Жёлтый тюльпан + повод `love` | «В классике жёлтый тюльпан — к разлуке; в современной флористике — к солнцу. Уточните посыл» |
| `white-mourning` | hard | Белая лилия / белая хризантема + `love`, `wedding` | «Белые лилии и хризантемы несут траурный подтекст — для свадьбы и признания лучше тёплые оттенки» |
| `landysh-chrys` | hard | Ландыш + хризантема | «Ландыш и хризантема плохо сочетаются и по этикету, и по стойкости» |

### 5.2 Расширение (можно отключить опцией)

| ID | Тип | Условие | Плашка |
|---|---|---|---|
| `mak-sleep` | soft | Мак + `birthday`, `baby` | «Мак — цветок сна и памяти; для радостных поводов он спорит с настроением» |
| `too-white` | soft | Белые (лилия/хризантема/роза/тюльпан) > 50 % стеблей при `love`/`wedding` | «Больше половины букета — белое: добавьте тёплый акцент» |
| `landysh-toxic` | soft | Ландыш + `baby` | «Ландыш токсичен — держите подальше от детей и животных» |
| `podsolnuh-scale` | soft | Подсолнух + `wedding` | «Подсолнух — очень крупный и «дачный»; для свадьбы он уместен только в стилизованном букете» |

### 5.3 Модель данных

Движок хранит правила в PHP-словаре `sad_znaniy_bouquet_conflicts()` (правится фильтром),
а быстрые пары дублируются в мета `_sz_fl_bad` для админки:

```text
[
  id     => 'landysh-ethylene',
  type   => 'hard' | 'soft',
  a      => ['landysh'],                 // цветок(и), которые запускают правило
  b      => ['roza-krasnaya', ...],      // второй цветок (для пар)
  scope  => 'always' | 'occasion:love,wedding' | 'share:white>50',
  text   => '…',
]
```

Проверка запускается после каждого изменения композиции; плашки не накапливаются —
показывается до 3 самых важных (`hard` выше `soft`).

| 24 | fallback | «Букет «{Слово}»» | «Букет «Тихий свет»» |

### 6.2 Генератор

1. `seed = hash( slugs + counts + occasion + to + reroll )` — детерминированный выбор,
   одна и та же композиция даёт одно и то же название до перегенерации.
2. Приоритет шаблона: `occasion+to` → `occasion` → доминирующая категория → `solo` → `fallback`.
3. Подстановки:
   - `{цветок}` — название цветка с максимальным `score` (в родительном падеже из словаря форм);
   - `{Эпитет}` — `Нежный / Тихий / Ясный / Тёплый / Светлый`;
   - `{чувство}` — `любовь / дружба / уважение / надежда / память`;
   - `{Слово}` — `Тихий свет / Тёплый вечер / Первый шаг / Дыхание сада`.
4. Ограничения: длина ≤ 60 символов, первая буква заглавная, без вложенных кавычек.
5. Перегенерация: `reroll++` циклически перебирает подходящие шаблоны; после исчерпания —
   комбинация «{Эпитет} {цветок}».
6. Fallback, если ни один шаблон не подошёл: «Букет «{Слово}»».

Падежи: для каждого цветка хранится форма родительного падежа в `_sz_fl_genitive`
(«роза» → «розы»), иначе используется конструкция «Букет: {название}».

## 7. Модель букета (JSON) и сохранение

### 7.1 Схема

```json
{
  "version": 1,
  "id": "f4c8e1b2a9d34c6f8b1e2d3c4a5b6c7d",
  "title": "Спасибо за тепло",
  "generated": true,
  "occasion": "thanks",
  "to": "mama",
  "solo": false,
  "items": [
    { "slug": "gerbera", "count": 3 },
    { "slug": "roza-rozovaya", "count": 2 }
  ],
  "reroll": 0,
  "created": "2026-10-18T12:00:00Z",
  "updated": "2026-10-18T12:10:00Z",
  "owner": 0
}
```

Правила схемы: `items` — только существующие `flower` slug; `count` 1–25; сумма стеблей ≤ 25;
`title` ≤ 120 символов; `solo` = (сумма стеблей = 1); `owner` = ID пользователя (0 для гостя).

### 7.2 Хранение

| Кто | Где | Ключи | Лимит |
|---|---|---|---|
| Гость | `localStorage` | `sz_bouquet_v1` (текущий), `sz_bouquets_v1` (список) | 10 букетов, 30 КБ |
| Залогиненный | `user_meta` | `_sz_bouquet_<uuid>`, индекс `_sz_bouquets` | 20 букетов |

Индекс: `[{ id, title, created, updated, occasion, to, stems }]` — для страницы «Мои букеты»
(аналог `_sz_plans` в `planner-cabinet.php`).

### 7.3 Валидация и безопасность (стандарт 7.3)

- UUID — 32 hex (`bin2hex( random_bytes( 16 ) )`), перебор нереален.
- `sad_znaniy_bouquet_normalize()`: белый список ключей, `occasion`/`to` — из словарей,
  `slug` — из опубликованных `flower`, `count` — `absint` с диапазоном, `title` — `sanitize_text_field`.
- Запись: nonce `wp_rest`, `permission_callback` — `is_user_logged_in()`;
  ключ меты строится от текущего пользователя, `owner` в теле сверяется.
- Чтение публичной ссылки — по UUID, без owner-check (read-only режим `?bouquet=<uuid>`).
- Вывод: `esc_html`/`esc_attr`/`esc_url` в PHP, `textContent` в JS. Никакого `innerHTML` с данными.

### 7.4 REST

| Метод | Маршрут | Доступ |
|---|---|---|
| `POST` | `/sad-znaniy/v1/bouquets` | залогиненный (создание/сохранение) |
| `GET` | `/sad-znaniy/v1/bouquets/view?id=<uuid>` | публично (read-only просмотр) |
| `DELETE` | `/sad-znaniy/v1/bouquets/delete?id=<uuid>` | владелец |
| `POST` | `/sad-znaniy/v1/bouquets/mail?id=<uuid>` | владелец (письмо, Партия 3) |
| `GET` | `/sad-znaniy/v1/bouquets/recommend?occasion=<key>&to=<key>` | публично (подбор) |
| `GET` | `/sad-znaniy/v1/bouquets/pdf?id=<uuid>` | залогиненный (данные для PDF) |

ID передаётся параметром запроса, а не сегментом пути: шаблон маршрута не содержит символа «больше» и не срабатывает защита транспорта на перенаправление.

Лимит писем — общий с планировщиком (`sad_znaniy_planner_mail_limit`, 10/час).

## 7б. Редактируемость справочника (трио)

Всё, что видит владелец, правится **без кода**:

| Что | Где в админке |
|---|---|

и публикует. Публикация — только действием владельца (правило проекта).

3. **Мини-карточка.** По клику (не добавлению): значение, 2–3 предложения, «Подробнее о цветке →»
   (если `_sz_fl_plant`), кнопка «Добавить в букет». Закрытие — Esc/крестик/клик вне.
   На мобайле — bottom-sheet.
4. **Композиция.** Дуга из кружков (радиус зависит от количества), каждый элемент —
   `.bk-stem` с `data-slug`; повторный клик добавляет стебель, `−/+` у выбранного.
   Счётчик стеблей, подсказка нечётности, плашки конфликтов (до 3), название (клик — reroll),
   ручная правка, кнопки действий.
5. **Действия.** «Сохранить» (гость — localStorage + плашка входа; залогиненный — REST),
   «Скачать PDF» (гейт), «Поделиться» (read-only ссылка), «Отправить письмом» (гейт).

## 9. Анимации (CSS only)

Бюджет: **только `transform` и `opacity`**, без анимации `width/height/top/left/box-shadow`.
Максимум 25 одновременно анимируемых узлов.

| Имя | Триггер | Что делает |
|---|---|---|
| `bk-pulse` | добавление цветка | круг 1 → 1.12 → 1 за 420 мс, лёгкий `opacity` |
| `bk-glow` | связь между выбранными кружками | псевдоэлемент с радиальным градиентом, `opacity` 0 → .6 → 0 |
| `bk-solo` | режим солитёра | «дыхание» 1 → 1.04 → 1, 3.2 с, бесконечно |
| `bk-stem-in` | новый элемент композиции | `translateY(12px)` + `scale(.92)` → норма, 260 мс |
| `bk-badge` | появление ✦ | `scale(.6)` → 1, 180 мс |

**rAF** используется только для расчёта геометрии дуги (позиции кружков) и пересчёта
при `resize` (debounce 120 мс): результат пишется в CSS-переменные `--bk-x/--bk-y`,
сами элементы двигаются трансформом. В цикле rAF нет чтения `offsetWidth/getBoundingClientRect`.

**Уважение к настройке:** при `prefers-reduced-motion: reduce` (уже есть в `main.css`)
все анимации отключаются, остаётся мгновенная смена состояния.

## 10. PDF, шаринг, письмо

### 10.1 Гейт регистрации

Как у планировщика (`sad_znaniy_planner_gate()`): гость при нажатии «Скачать PDF» видит
стеклянное окно с формой входа WordPress и ссылкой «Создать аккаунт»; после входа
возвращается на `/konstruktor-buketa/?print=1` — печать запускается автоматически.
Гейт отключается галочкой в «Внешний вид → Сад знаний» (опция `sad_znaniy_bouquet_gate`).
«Поделиться» и read-only просмотр — без гейта.

### 10.2 PDF: 2 страницы A4

**Лист 1 — букет:**
- шапка: логотип «Сад знаний» + адрес сайта; справа — кто собрал (залогиненный: имя и e-mail)
  и дата; для гостя — «Создано в конструкторе Сад знаний»;
- название букета крупно;
- строка «Повод · Кому»;
- композиция: `canvas` → `img` (круги с фото/буквами, дуга), экспорт в PNG ×2 для печати;
- легенда значений: «цветок — значимость» (до 10 строк);
- QR 34×34 мм + подпись «Наведите камеру — откроется сайт» (`assets/img/qr-site.svg`);
- декор PNG по краям (2–4 файла);
- слот баннера (`.ad-slot`, заглушка).

**Лист 2 — значения и уход:**
- описания цветов букета (до 12): название, значимость, 2–3 предложения;
- ссылки «Уход за {цветок} →» на карточку `plant`, если связь есть;
- блок «Полезно знать»: 3–4 статьи-гайда;
- сетка «Больше инструментов» (иконки + названия, как на 4-м листе планировщика);
- подвал: сайт, QR (опционально), «Собрано в конструкторе букета».

Печать — `@page { size: A4; margin: 14mm }`, `page-break-after` между листами,
скрытие интерфейса через `@media print` (образец — `assets/css/planner.css`).
Размеры `width/height` картинок берутся из `getimagesize()` (как у калькуляторов).

### 10.3 «Поделиться»

- Ссылка `?bouquet=<uuid>` — read-only: композиция, значения, название; действия скрыты,
  есть кнопка «Создать копию себе» (гость → localStorage, залогиненный → REST).
- Кнопки: «Скопировать ссылку» + нативная «Поделиться» (если поддерживается).
- Мета-теги: `og:title` = название букета, `og:description` = повод/кому + состав.

### 10.4 «Отправить письмом»

- `POST /sad-znaniy/v1/bouquets/<id>/mail` (только владелец, nonce).
- Проверки: `is_email()`, запрет служебного адреса сайта, лимит 10/час на пользователя
  (общая опция с планировщиком), журнал в «Безопасность → Почта (локалка)».
- Тема: «Букет „{название}“ — {повод} — {сайт}».
- Тело: состав (цветок — количество), значения, ссылка на read-only просмотр, подпись сайта.
- Ошибки — человеческим языком: «Проверьте адрес…», «Лимит писем исчерпан…».
