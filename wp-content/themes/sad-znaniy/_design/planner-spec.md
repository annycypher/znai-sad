## 1. Модель данных плана (JSON)

Один план = один JSON. Координаты в метрах, начало координат — левый верхний угол участка.

```json
{
  "version": 1,
  "id": "f4c8e1b2-…",          // UUID v4, генерируется при создании
  "meta": {
    "title": "Шесть соток",
    "region": "srednyaya",     // ключ sad_znaniy_regions() (без «Все регионы»)
    "created": "2026-10-06T12:00:00Z",
    "updated": "2026-10-06T12:30:00Z"
  },
  "plot": {
    "shape": "rect",           // MVP: только прямоугольник
    "width": 30,               // м, ось X
    "height": 40,              // м, ось Y
    "north": "up"              // задел: север всегда вверх (-Y)
  },
  "elements": [
    {
      "id": "e_8f3a2c",
      "type": "bed",           // ключ из §2
      "x": 4.0, "y": 5.5,      // центр элемента, м
      "width": 3.0, "height": 1.0,
      "rotation": 0,           // градусы, поворот вокруг центра
      "crop": 14,              // ID растения (plant) или null
      "label": ""              // произвольная подпись
    }
  ],
  "gridStep": 0.5              // шаг сетки (MVP фиксирован 0,5 м)
}
```

Хранение:
- гость — `localStorage['sz_plan_{id}']` (план по ключу) + индекс `sz_plan_index`;
- залогиненный — `user_meta` (автосохранение 30 с + `beforeunload`), список планов в кабинете;
- read-only — открытие по `?plan=UUID` без панелей редактирования.

### Версионирование и миграции

- `version` — целое, растёт при несовместимом изменении схемы (текущая — **1**).
- План с `version` **больше** текущей → открывается только для чтения с предупреждением «план создан более новой версией планировщика» (не пытаться править и сохранять).
- План с `version` **меньше** текущей → прогон миграций по цепочке (`migrate_1_to_2()`, `migrate_2_to_3()`…), результат сразу сохраняется; перед миграцией исходный JSON копируется в `localStorage['sz_plan_backup_{id}']`.
- Миграции живут в `assets/js/planner-migrations.js` (появляются в Партии 1, пока файл пуст — версия 1).
- Ключи хранения: `sz_plan_{uuid}` — тело плана; `sz_plan_index` — список `{id, title, updated, region}`; `sz_plan_hints` — скрытые пользователем подсказки; `sz_plan_ui` — зум/панорама/сетка (не часть плана, не синхронизируется).
- Серверная копия для залогиненных — `user_meta`: `_sz_plan_{uuid}` (тот же JSON и та же версия) и индекс `_sz_plans` (список id).

## 3. Модель подсказок

Подсказка — карточка у элемента (заголовок, текст, крестик, «не показывать для этой пары»). Поведение — как карточки в календаре: не перекрывает работу, закрывается крестиком, не накапливается.

Уровни (цвет карточки):
- `good` (зелёная) — хорошие соседи;
- `bad` (красная) — плохие соседи;
- `warn` (жёлтая) — светолюбивая культура в тени.

Структура подсказки:

```json
{
  "id": "hint_e8f3a2c_compat",
  "severity": "bad",
  "title": "Плохие соседи",
  "text": "Томат и капуста рядом угнетают друг друга.",
  "pair": "14:18",
  "rule": "compat"
}
```

### Правила движка

1. **Совместимость (`compat`).** Срабатывает при добавлении / перемещении / смене культуры у элементов типа `bed`/`tree`/`shrub`, когда зазор между двумя элементами с культурами ≤ 1 м. Пара культур сверяется по `_sz_plant_neighbors_good` / `_sz_plant_neighbors_bad` (матчинг — по названию растения, регистронезависимо, вхождение строки; мета — свободный текст). Найдено в «хороших» → `good`, в «плохих» → `bad`.
2. **Свет (`shade`).** Срабатывает при изменении геометрии. Зоны тени:
   - «дом» (`building`): прямоугольник от северной грани дома на 3 м на север (вверх, −Y), шириной с дом;
   - «дерево» (`tree`): круг с центром в центре дерева, радиус кроны = `max(width, height) / 2`.
   Если элемент с культурой, у которой `_sz_plant_light === 'sun'`, пересекается с зоной тени → `warn`. «Север» в MVP — всегда вверх.
3. **pH-конфликты — не в MVP** (перенесено в Партию 4).

### Отключение
Крестик закрывает карточку до следующего пересчёта; «не показывать для этой пары» пишет пару/правило в `localStorage['sz_plan_hints']` и больше её не поднимает.

### Приоритеты и порядок показа

- Приоритет уровней: **`bad` → `warn` → `good`**.
- У одного элемента показывается не больше двух карточек: сначала `bad`, затем `warn`, затем `good`. Всего на экране — не больше трёх карточек; остальные попадают в правую панель «Сводка участка → Конфликты» (списком, с подсветкой элементов).
- Одна карточка на пару «элементы + правило»: ключ `hint_{idA}_{idB}_{rule}`; повторно для той же пары не поднимается, но при смене геометрии или культуры пересчитывается (скрытое пользователем — не показывается).
- Порядок правил при одинаковом уровне: `compat` → `shade` → `ph` (Партия 4).
- Подсказка **не блокирует** действие: пользователь может расставить всё как удобно, конфликты только подсвечиваются и считаются в сводке (число «конфликтов: N»).

### pH и почва (Партия 4, заготовка правила)

Считается для культур в соседних элементах (зазор ≤ 1 м, как в `compat`), по `_sz_plant_ph_from` / `_sz_plant_ph_to`, затем `_sz_plant_soil`:
- пересечение диапазонов есть, но узкое (меньше 0,5 ед.) → `warn` «разная кислотность, нужен компромисс»;
- пересечения нет → `bad` «несовместимая кислотность»;
- несовпадение текста `_sz_plant_soil` → `warn` (приоритет ниже pH, формулировки согласуем в Партии 4).

## 4. Мокап интерфейса (текст)

### Десктоп (ширина ≥ 1024 px)
- **Шапка сайта** — общая, как на остальных страницах.
- **Верхняя панель инструментов** (над canvas): название плана (клик — переименовать), селект региона, кнопки «↶ / ↷» (undo/redo), «− / +» (зум), «Сетка» (вкл/выкл), справа — статус сохранения («Сохранено / Сохраняется…»).
- **Левая вертикальная панель** — палитра: 9 кнопок с иконкой и подписью; клик по кнопке → режим размещения (курсор меняется), клик по canvas ставит элемент.
- **Центр — canvas**: сетка 0,5 м, привязка к сетке, зум (кнопки + колесо + Ctrl+колесо), панорамирование (зажатая левая кнопка на пустом месте / пробел + тянуть). Выбранный элемент — рамка с маркерами: перетаскивание = перемещение, маркеры по углам = размер, маркер поворота сверху.
- **Правая панель** — свойства выбранного элемента: тип, размеры (в метрах), поворот, культура (поиск по названию, превью-карточка при наведении), кнопка «Удалить». Если ничего не выбрано — **Сводка участка**: список культур, площади, конфликты, свободные места.
- **Низ** — кнопки экспорта («Печать/PDF», «JPG», «Отправить») и «Мои планы / Войти».

### Мобильный (< 768 px)
- Canvas на весь экран, сайт-шапка свёрнута.
- **Нижняя панель** (свайп вверх раскрывает): палитра элементов + инструменты (undo/redo, зум, сетка). По умолчанию не перекрывает нижнюю треть экрана.
- Жесты: pinch — зум, один палец — панорама/перетаскивание, тап — выбор/размещение. Хит-зоны элементов ≥ 44 px.
- Свойства элемента — нижний лист (bottom sheet) поверх canvas.

### Общие состояния
- **Пустой план**: canvas с сеткой + подсказка «Выберите элемент слева и кликните по участку».
- **Гость**: плашка «Сохраняется только в этом браузере. Войдите — план будет всегда под рукой».
- **Read-only (`?plan=UUID`)**: без панелей редактирования, только кнопки экспорта и «Создать копию себе».

## 6. Фиксированные технические решения (промпт старта 07.10.2026)

- **Только vanilla JS + Canvas**, без библиотек и внешних сервисов (правило проекта: никаких запросов вне домена, стиль как у `calendar.js`).
- **Данные — из CPT `plant`**, дублирующих справочников не создаём.
- **Сохранение:** гость — localStorage; залогиненный — кабинет (`user_meta`), автосохранение раз в 30 с и на `beforeunload`.
- **Регион — из `region.js`:** `window.szRegion.getRegion()` и подписка `window.szRegion.onChange()` (событие `sz:region-change`); смена региона в шапке пересчитывает рекомендации без перезагрузки страницы.
- **Экспорт:** печать/PDF — системный диалог; JPG — `canvas.toDataURL`; «Поделиться» — Web Share API с откатом на копирование ссылки; «Отправить» — ссылка на план (`?plan=UUID`) без серверной отправки данных.
- **Инструменты разработки:** все скрипты в `_tools/` с CLI-guard; JSON-выгрузки проверяются схемой (`_tools/schema-sample-*.json` + `_tools/validate-schema.ps1`) — стандарт, принятый в Этапе 7.3.

## 7. Контракт данных для клиента

На странице планировщика печатается один JSON-payload (на старте — без REST-запросов):

```json
{
  "version": 1,
  "regions": [{ "key": "srednyaya", "label": "Средняя полоса" }],
  "currentRegion": "srednyaya",
  "plants": [
    {
      "id": 14, "title": "Томат", "slug": "tomat",
      "light": "sun", "water": "moderate",
      "ph": [5.5, 6.5], "soil": "рыхлая, плодородная",
      "good": "базилик, морковь", "bad": "картофель, капуста"
    }
  ]
}
```

- Совместимость передаётся текстом (`good` / `bad`); разбор и матчинг по названиям выполняет клиент (индекс `title → id` строится один раз при загрузке).
- Полная карточка растения — по адресу `/rasteniya/{slug}/`; превью подтягивается при первом наведении и кэшируется в памяти (второй раз то же растение не запрашивается).
- Регион влияет на рекомендации (сроки/пригодность) — источник данных тот же, что у календаря и лунного календаря; конкретные правила для планировщика появятся в Партии 4 (сезонные окна `_design/season-windows.md`).
