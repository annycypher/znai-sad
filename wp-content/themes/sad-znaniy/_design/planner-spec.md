## 1. Модель данных плана (JSON)

Один план = один JSON. Координаты в метрах, начало координат — левый верхний угол участка.

```json
{
  "version": 1,
  "id": "f4c8e1b2-…",          // UUID v4, генерируется при создании
  "meta": {
    "title": "Шесть соток",
    "region": "srednyaya",     // ключ sad_znaniy_regions() (без «Все регионы»)
    "created": "2026-10-06T12:00:00Z",
    "updated": "2026-10-06T12:30:00Z"
  },
  "plot": {
    "shape": "rect",           // MVP: только прямоугольник
    "width": 30,               // м, ось X
    "height": 40,              // м, ось Y
    "north": "up"              // задел: север всегда вверх (-Y)
  },
  "elements": [
    {
      "id": "e_8f3a2c",
      "type": "bed",           // ключ из §2
      "x": 4.0, "y": 5.5,      // центр элемента, м
      "width": 3.0, "height": 1.0,
      "rotation": 0,           // градусы, поворот вокруг центра
      "crop": 14,              // ID растения (plant) или null
      "label": ""              // произвольная подпись
    }
  ],
  "gridStep": 0.5              // шаг сетки (MVP фиксирован 0,5 м)
}
```

Хранение:
- гость — `localStorage['sz_plan_{id}']` (план по ключу) + индекс `sz_plan_index`;
- залогиненный — `user_meta` (автосохранение 30 с + `beforeunload`), список планов в кабинете;
- read-only — открытие по `?plan=UUID` без панелей редактирования.

### Версионирование и миграции

- `version` — целое, растёт при несовместимом изменении схемы (текущая — **1**).
- План с `version` **больше** текущей → открывается только для чтения с предупреждением «план создан более новой версией планировщика» (не пытаться править и сохранять).
- План с `version` **меньше** текущей → прогон миграций по цепочке (`migrate_1_to_2()`, `migrate_2_to_3()`…), результат сразу сохраняется; перед миграцией исходный JSON копируется в `localStorage['sz_plan_backup_{id}']`.
- Миграции живут в `assets/js/planner-migrations.js` (появляются в Партии 1, пока файл пуст — версия 1).
- Ключи хранения: `sz_plan_{uuid}` — тело плана; `sz_plan_index` — список `{id, title, updated, region}`; `sz_plan_hints` — скрытые пользователем подсказки; `sz_plan_ui` — зум/панорама/сетка (не часть плана, не синхронизируется).
- Серверная копия для залогиненных — `user_meta`: `_sz_plan_{uuid}` (тот же JSON и та же версия) и индекс `_sz_plans` (список id).

## 3. Модель подсказок

Подсказка — карточка у элемента (заголовок, текст, крестик, «не показывать для этой пары»). Поведение — как карточки в календаре: не перекрывает работу, закрывается крестиком, не накапливается.

Уровни (цвет карточки):
- `good` (зелёная) — хорошие соседи;
- `bad` (красная) — плохие соседи;
- `warn` (жёлтая) — светолюбивая культура в тени.

Структура подсказки:

```json
{
  "id": "hint_e8f3a2c_compat",
  "severity": "bad",
  "title": "Плохие соседи",
  "text": "Томат и капуста рядом угнетают друг друга.",
  "pair": "14:18",
  "rule": "compat"
}
```

### Правила движка

1. **Совместимость (`compat`).** Срабатывает при добавлении / перемещении / смене культуры у элементов типа `bed`/`tree`/`shrub`, когда зазор между двумя элементами с культурами ≤ 1 м. Пара культур сверяется по `_sz_plant_neighbors_good` / `_sz_plant_neighbors_bad` (матчинг — по названию растения, регистронезависимо, вхождение строки; мета — свободный текст). Найдено в «хороших» → `good`, в «плохих» → `bad`.
2. **Свет (`shade`).** Срабатывает при изменении геометрии. Тень задаётся полем `shadow` в `TYPES` (Дерево 2,5 м, Куст 1 м, Дом 3 м) — геометрия зон переносится из демо 1:1:
   - «дом» (`house`): зона к северу от дома (вверх, −Y) глубиной `shadow`;
   - «дерево» (`tree`) и «куст» (`bush`): круг с центром в центре элемента радиусом `shadow`.
   Если элемент с культурой, у которой `_sz_plant_light === 'sun'`, попадает в зону тени → `warn`. «Север» в MVP — всегда вверх.
3. **pH-конфликты — не в MVP** (перенесено в Партию 4).

### Отключение
Крестик закрывает карточку до следующего пересчёта; «не показывать для этой пары» пишет пару/правило в `localStorage['sz_plan_hints']` и больше её не поднимает.

### Приоритеты и порядок показа

- Приоритет уровней: **`bad` → `warn` → `good`**.
- У одного элемента показывается не больше двух карточек: сначала `bad`, затем `warn`, затем `good`. Всего на экране — не больше трёх карточек; остальные попадают в правую панель «Сводка участка → Конфликты» (списком, с подсветкой элементов).
- Одна карточка на пару «элементы + правило»: ключ `hint_{idA}_{idB}_{rule}`; повторно для той же пары не поднимается, но при смене геометрии или культуры пересчитывается (скрытое пользователем — не показывается).
- Порядок правил при одинаковом уровне: `compat` → `shade` → `ph` (Партия 4).
- Подсказка **не блокирует** действие: пользователь может расставить всё как удобно, конфликты только подсвечиваются и считаются в сводке (число «конфликтов: N»).

### pH и почва (Партия 4, заготовка правила)

Считается для культур в соседних элементах (зазор ≤ 1 м, как в `compat`), по `_sz_plant_ph_from` / `_sz_plant_ph_to`, затем `_sz_plant_soil`:
- пересечение диапазонов есть, но узкое (меньше 0,5 ед.) → `warn` «разная кислотность, нужен компромисс»;
- пересечения нет → `bad` «несовместимая кислотность»;
- несовпадение текста `_sz_plant_soil` → `warn` (приоритет ниже pH, формулировки согласуем в Партии 4).

Активное состояние — `.tb.on` (зелёная заливка). **Дополняем демо:** селект региона и кнопка **«🔗 Поделиться»** (зелёная, §9).
- **Левая выезжающая панель** (`.side-left`, drawer + backdrop): «Элементы участка» — палитра **10 кнопок** (`.pal-item`, `data-type`) с иконкой и подписью; ниже подсказка по жестам («угол элемента — размер, центр — перенос, угол участка — размер участка, Alt+клик — копия, колесо/щипок — зум, пустое место — панорама»).
- **Центр — canvas** (`#board` в стеклянной рамке `.board-shell`): фон участка, сетка тремя слоями (0,5 м при зуме ≥ 7 px/м, 1 м при ≥ 3, 5 м при ≥ 2,2; каждая группа линий — одним `stroke`), подписи размеров участка, элементы, размерные линии выбранного, углы участка (когда ничего не выбрано), справа сверху — круглые кнопки зума (`+`, `−`, «вписать»).
- **Низ canvas** — строка «Итог» (`.bottomline`, скрыта, пока план пуст): площадь, число элементов, культуры, конфликты.
- **Тосты-подсказки** (`.toasts` сверху по центру): карточка с цветной точкой (`red`/`yellow`/`green`), заголовком, текстом, крестиком и кнопкой **«не показывать»** (пишется в `sz_plan_hints`). Плюс нижняя строка-подсказка `.hint-chip`.
- **Правая выезжающая панель** (`.side-right`): «Свойства выбранного» — тип, Ш × Д (шаг 0,5 м), **поиск культуры** с автодополнением (`cropSearch` + `cropList`), «⧉ Дублировать», «Удалить элемент»; карточка «🌱 Участок» (Ш × Д участка); ниже — **«Сводка участка»** (площадь, элементы, культуры с площадями, блок `.conflict` с конфликтами).
- **Мастер первого шага** (`.wizard`, оверлей, 3 шага с точками прогресса): 1) «Давайте спланируем участок» — два числа (Ш × Д, 4…100 м, по умолчанию 20 × 30); 2) «Где стоит дом?» — клик по схеме ставит дом; 3) «Что хотите выращивать?» — сетка культур 3×N → «Создать план ✓». В нашей версии список культур — из CPT `plant`.
- **Лист экспорта** (`.export-sheet`): в демо «📤 Отправить / 🖼 JPG / 🖨 Печать / PDF / ✕ Закрыть» → у нас **«🔗 Поделиться» (зелёная), «🖼 JPG», «🖨 Печать / PDF», «✕ Закрыть»** (§9).
- **Печать/PDF** (`#print-doc`, 3 страницы): 1) название плана, подзаголовок (регион, площадь, дата), картинка плана, статистика, легенда культур, футер «Сад знаний · znai-sad.ru»; 2) таблица «Сводка участка»; 3) «Рекомендации по культурам плана» (таблица ухода + примечание про сроки и дозы).

### Мобильный (< 768 px)
- Canvas на весь экран, тулбар — компактная строка, панели выезжают снизу/сбоку, **нижний док** (`.m-bottom`): «Элементы», «Отменить», «План», «Размеры», «Экспорт», «Сводка» (активный пункт — `.on`).
- Жесты: щипок — зум, один палец — панорама/перенос, тап — выбор/размещение; Alt недоступен (копия — кнопкой «Дублировать»). Хит-зоны ≥ 44 px, `env(safe-area-inset-bottom)` для айфонов.
- Экспорт-лист поднимается над доком, свойства элемента — нижним листом.

### Общие состояния
- **Пустой план**: участок с сеткой + строка-подсказка «Выберите элемент · колесо — зум · углы участка — размер · пустое место — панорама».
- **Гость**: плашка «Сохраняется только в этом браузере. Войдите — план будет всегда под рукой».
- **Read-only (`?plan=UUID`)**: без панелей редактирования, только экспорт и «Создать копию себе».
- **Сохранение**: индикатор в тулбаре; ошибка сохранения — тост `red`.

Мастер первого шага — часть базовой функциональности: переносим в Партию 1 вместе с каркасом, как в демо.

## 6. Фиксированные технические решения (промпт старта 07.10.2026)

- **Только vanilla JS + Canvas**, без библиотек и внешних сервисов (правило проекта: никаких запросов вне домена, стиль как у `calendar.js`).
- **Данные — из CPT `plant`**, дублирующих справочников не создаём.
- **Сохранение:** гость — localStorage; залогиненный — кабинет (`user_meta`), автосохранение раз в 30 с и на `beforeunload`.
- **Регион — из `region.js`:** `window.szRegion.getRegion()` и подписка `window.szRegion.onChange()` (событие `sz:region-change`); смена региона в шапке пересчитывает рекомендации без перезагрузки страницы.
- **Экспорт:** печать/PDF — системный диалог; JPG — `canvas.toDataURL`; «Поделиться» — Web Share API с откатом на копирование ссылки; «Отправить» — ссылка на план (`?plan=UUID`) без серверной отправки данных.
- **Инструменты разработки:** все скрипты в `_tools/` с CLI-guard; JSON-выгрузки проверяются схемой (`_tools/schema-sample-*.json` + `_tools/validate-schema.ps1`) — стандарт, принятый в Этапе 7.3.

## 7. Контракт данных для клиента

На странице планировщика печатается один JSON-payload (на старте — без REST-запросов):

```json
{
  "version": 1,
  "regions": [{ "key": "srednyaya", "label": "Средняя полоса" }],
  "currentRegion": "srednyaya",
  "plants": [
    {
      "id": 14, "title": "Томат", "slug": "tomat",
      "light": "sun", "water": "moderate",
      "ph": [5.5, 6.5], "soil": "рыхлая, плодородная",
      "good": "базилик, морковь", "bad": "картофель, капуста"
    }
  ]
}
```

- Совместимость передаётся текстом (`good` / `bad`); разбор и матчинг по названиям выполняет клиент (индекс `title → id` строится один раз при загрузке).
- Полная карточка растения — по адресу `/rasteniya/{slug}/`; превью подтягивается при первом наведении и кэшируется в памяти (второй раз то же растение не запрашивается).
- Регион влияет на рекомендации (сроки/пригодность) — источник данных тот же, что у календаря и лунного календаря; конкретные правила для планировщика появятся в Партии 4 (сезонные окна `_design/season-windows.md`).

## 8. Адаптивность (требование владельца: «под любые устройства»)

Проверяем живьём (устройство/эмулятор), список обязательный:

| Что | Требование |
|---|---|
| Диапазон ширин | 320 px (iPhone SE) → 1440 px (ноутбук) → 2560 px (4K): ничего не ломается и не перекрывается |
| Ориентация | портрет и ландшафт на телефоне и планшете: canvas пересчитывается, док занимает не больше 25 % высоты |
| Низкое окно | 568 px высоты (старый iPhone в ландшафте): все инструменты доступны, панели скроллятся внутри себя |
| Меню и инструменты | тулбар переносится на вторую строку, при нехватке — сворачивается в «⋯»; палитра и свойства — выезжающие панели, закрываются по backdrop и Escape |
| Тач-цели | кнопки ≥ 44 × 44 px, промежутки ≥ 8 px; Alt-копия недоступна — есть «Дублировать» |
| Зум страницы | браузерный зум 200 % (WCAG): интерфейс остаётся рабочим |
| Safe-area | отступы `env(safe-area-inset-*)` для айфонов с «вырезом» |
| Печать / JPG | план масштабируется под A4 без обрезки, 3 страницы не разъезжаются |
| Плавность | перетаскивание ≥ 50 fps на планшете: перерисовка через `requestAnimationFrame`, штрихи сетки пакетами (как в демо) |

## 9. «Поделиться» — зелёная кнопка, как в календаре

- Вид: фон `var(--emerald)` (#0E9F6E), при наведении `var(--emerald-dark)`, текст `var(--on-emerald)`, тень `var(--emerald-shadow)`, скругление-пилюля, иконка «🔗» + «Поделиться». На мобильном — крупная кнопка в доке/плавающей панели (как `fabShare` в календаре), на десктопе — в тулбаре и в листе экспорта.
- Поведение 1:1 как в `calendar.js`: при поддержке `navigator.share({ title, text, url })`, иначе — копирование ссылки и состояние кнопки «✓ Ссылка скопирована» на 2 секунды.
- Ссылка — `?plan=UUID` (read-only просмотр). Локально содержит `sadznaniy.local`, после переноса — боевой домен.
- Только Web Share API и буфер обмена: никаких сторонних сервисов (правило проекта).

## 10. Что берём из демо 1:1, что меняем, что нужно решить

**Берём как есть:** типы и цвета (§2), иконки, константы (SNAP 0,5; PMIN/PMAX; зум 4–48, «вписать»), поведение указателя (углы участка и элемента, Alt-копия, панорама, щипок), сетка тремя слоями, панели/тосты/док/лист экспорта, печать в 3 страницы, строка «Итог», история 40 шагов, стекло/неоморфизм.

**Меняем (наши данные вместо демо-констант):**
1. `CROPS` (14 захардкоженных культур) → **76 растений из CPT `plant`**; поля `light`, `soil`, `bad`, `good` берём из наших мета, а `water`/`feed` (тексты ухода в демо) в базе отдельно не хранятся.
2. Схема плана — как в §1 (с `version`, UUID, хранением в кабинете для залогиненных).
3. Регион — селект в тулбаре + `region.js` (`getRegion()` / `onChange()`).
4. Экспорт — в листе и в доке, «Отправить» заменяется зелёной «Поделиться» (§9).

**Нужны решения владельца (до Партии 2):**
1. **Цвет культуры.** В демо цвет есть у каждой культуры, у наших растений — нет. Варианты: (а) по разделу (`plant_section`: Сад / Огород / Цветы); (б) по типу (`plant_type`: дерево / куст / многолетник / однолетник / овощ); (в) авто-палитра по ID. Предлагаю **(б)**.
2. **Тексты ухода в печати** («полив», «подкормка»): (а) первый абзац блока ухода из статьи растения; (б) короткие фразы из нашей мета (`_sz_plant_water`, `_sz_plant_soil`); (в) не печатать таблицу ухода вовсе. Предлагаю **(б)**.
3. **Матчинг совместимости:** предлагаю по названию растения (регистронезависимо, вхождением) + нормализация окончаний («томаты» / «томат»), плюс поддержка слага, если он встретится в тексте мета.
4. **Культуры в мастере (шаг 3):** предлагаю 9 популярных — Томат, Огурец, Картофель, Морковь, Клубника, Цветы (раздел), Яблоня, Зона отдыха/Газон, Ягодные.
