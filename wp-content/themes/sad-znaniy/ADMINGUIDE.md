<a id="статьи"></a>
## 1. Статьи (блог)

**Где:** админка → **Записи → Добавить запись**.

1. Заполните **Заголовок**.
2. В блоках выберите паттерн: кнопка **«+»** → вкладка **«Образцы» (Patterns)** → категория **«Сад знаний»** → **«Гайд по растению»**. Подставится готовая структура: вступление → фото → разделы H2 → чек-лист → FAQ. Замените текст заготовки на свой.
3. **Фото записи** (обложка): панель справа → **Запись → Изображение записи → Задать**. Без обложки карточка статьи выйдет без картинки — это нормально.
4. Выберите **Рубрику** (справа → Рубрики). Для обычных статей — любая, кроме «Рецепты».
5. **Опубликовать**.

**Где появится:** последние 2 статьи — в блоке **«Блог и советы»** на главной; все статьи — на странице «Все статьи» (кнопка в том же блоке).

**Как задать страницу «Все статьи»:** админка → **Настройки → Чтение** → «На главной отображать» → поставьте «Статическую страницу» (Главная) и в поле **«Страница записей»** выберите страницу «Статьи». Тогда кнопка «Все статьи» ведёт на неё.

<a id="рецепты"></a>
## 2. Рецепты

Рецепты — это обычные **записи** в отдельной рубрике «Рецепты», а не отдельный раздел.

1. Админка → **Записи → Добавить запись**.
2. Паттерн **«Рецепт»** («+» → Образцы → «Сад знаний»): состав → шаги → совет.
3. В блоке справа **Рубрики** отметьте **«Рецепты»**.
4. Опубликуйте.

**Где появится:** в архиве рубрики «Рецепты» — `http://sadznaniy.local/category/retsepty/`.
Чтобы этот раздел был в меню: **Внешний вид → Меню →** добавьте в меню пункт **«Рубрики → Рецепты»**.

<a id="события"></a>
## 3. События календаря

**Где:** админка → **События → Добавить событие**.

1. **Заголовок** — что делать (например, «Высадка томатов в теплицу»).
2. **Текст** — подробности действия + конкретика (глубина, норма, температура).
3. Панель справа → блок **«Параметры события»**:
   - **Дата начала** — обязательна (по ней строится календарь и сортировка);
   - **Дата окончания** — необязательна;
   - **Регионы** — отметьте один или несколько (Юг / Средняя полоса / Урал / Сибирь / Дальний Восток) либо поставьте галочку **«Для всех регионов»**;
   - **Культура** — выберите растение из списка (связка для блока «Подробнее»);
   - **Сложность** — Новичок / Опытный / Всем;
   - **Приоритет** — Обязательно / Желательно / По погоде;
   - **Подсказка по погоде** — короткая пометка (например, «при сухой почве»);
   - **Повторять ежегодно** — галочка стоит по умолчанию: событие показывается в этом месяце каждый год, заводить его заново для следующего года не нужно. Снимите галочку, если событие разовое (только для указанного года).
4. Панель справа → блок **«Тип работы»** — отметьте один или несколько типов (Посев, Посадка, Полив, Подкормка, Обрезка, Защита, Сбор, Подготовка). У каждого типа свой цвет — в списке он показывается цветным чипом.
5. Опубликуйте.

**Где появится:** страница **«Календарь дачника»** — `http://sadznaniy.local/kalendar/` (сетка месяца, фильтры по региону/опыту/работам, список задач).
На главной — блок **«Календарь работ»**: 3 ближайших события по региону, который посетитель выбрал на странице календаря (хранится в браузере). Регион не выбран — блок скрыт. Прошедшие события в календаре помечаются «Пропущено».

**Список событий** (админка → События) показывает колонки **Дата**, **Работы** (цветные чипы) и **Регион**, по умолчанию сортирует по дате (ближайшие сверху).

### Как вести календарь

В начале каждого месяца готовьте следующий месяц:

1. Создавайте события **черновиками** (пакетом), затем публикуйте.
2. **Покрывайте регионы реалистично**: Юг — раньше, Сибирь и Дальний Восток — позже. Общие работы (подготовка теплицы, прополка) отмечайте **«Для всех регионов»**.
3. **Тип работы** — ставьте один основной (цвет покажется маркером в сетке и чипом в списке).
4. **Культура** — привязывайте растение, чтобы в карточке появился блок **«Подробнее»** со ссылками на растение, раздел и статьи.
5. **Сложность** и **приоритет** — чтобы работали фильтр «Новичок» и бейдж «Обязательно».
6. В тексте — конкретика (глубина, норма, температура). Сомнительные дозировки помечайте `⚠️ ФАКТ-проверить` и сверяйте перед публикацией.
7. После публикации проверьте месяц на `/kalendar/?month=N&year=YYYY`.

<a id="лунный-календарь"></a>
## 3.1 Лунный календарь

Страница **`/lunnyj-kalendar/`** — лунный посевной календарь: по дням месяца показывает фазу Луны, знак зодиака и «благоприятно / неблагоприятно» для работ.

**Как править справочник интерпретации:** админка → **Внешний вид → Лунный справочник**.
- **Фаза Луны — благоприятные работы** — что советуем в новолуние / растущую / полнолуние / убывающую.
- **Фаза Луны — неблагоприятные работы** — что в эти фазы делать не советуем (дни покоя).
- **Стихия знака — благоприятные работы** — огонь → плоды, земля → корнеплоды, воздух → цветы, вода → листовые.

Отметьте галочками нужные типы работ (Посев, Посадка, Обрезка, Подкормка, Защита, Сбор…) и сохраните. Фаза Луны и знак зодиака считаются автоматически (астрономия) — их править не нужно. Канон «благоприятно / неблагоприятно» — ваша экспертная настройка.

### Лунный календарь: SEO-обслуживание

**Где:** админка → **Внешний вид → Лунный справочник**, блок **«SEO и интро по месяцам»**.

- **Title / Description** — пусто = подставляется автоматически (title: «Лунный посевной календарь на {месяц} {год}: благоприятные дни по культурам»; description: «{N} благоприятных дней для посадки…»). Свой текст заменит авто.
- **Интро** — 2–3 абзаца своего текста на месяц (абзацы разделяйте пустой строкой). Пусто — блок не показывается.
- Страница отдаётся роботу целиком (SSR), плюс разметка **ItemList + FAQPage + BreadcrumbList**.

### Лунный календарь: категории растений и перелинковка

У каждого растения есть поле **«Лунная категория»** (админка → **Растения** → нужное растение → блок «Параметры выращивания»): Плоды и ягоды / Корнеплоды и лук / Зелень и листовые / Цветы и декоративные. Категория связывает растение со стихией знака, благоприятной для его органов.

Что это даёт:
- на странице растения появляется блок **«Лунные дни для посадки»** — благоприятные числа текущего и следующего месяца со ссылкой на календарь;
- в фильтре **«Показать дни для культуры»** на `/lunnyj-kalendar/` растения сгруппированы по категориям: выбрав, например, «Томат», вы подсветите дни категории «Плоды и ягоды».

Если категория у растения не задана — блок и пункт фильтра для него не выводятся. Заполнены все 64 растения; проверяйте категорию при добавлении новых.

### Лунный календарь: FAQ и страницы по культурам

**Частые вопросы** правятся в админке: **Внешний вид → Лунный справочник**, блок **«Частые вопросы (FAQ)»**. Одна строка = один вопрос в формате `вопрос | ответ`, в ответах можно ставить ссылки. Подстановки: `{crop}` — культура месяца, `{month_in}` — «в мае», `{month_name}` — «Май», `{year}`, `{good_days}` — ближайшие благоприятные даты, `{good_count}` — их число, `{bad_days}` — дни покоя, `{base_url}` — адрес сайта. Пусто — набор по умолчанию (6 вопросов). Те же вопросы уходят в разметку FAQPage (без HTML-тегов).

**Страницы по культурам (48 URL):** `/lunnyj-kalendar/{месяц}/{культура}/`, где культура — `plody`, `korneplody`, `zelen`, `tsvety`. Это отдельные индексируемые страницы («благоприятные дни для плодов и ягод в мае»): своя шапка и описание, вводный абзац с конкретными датами и подсветка подходящих дней. Старые адреса `?culture=…` теперь 301-редиректят на ЧПУ. Флаг **«Страницы категорий в sitemap.xml»** включает/выключает эти адреса в карте сайта.

**Перелинковка со статьями:** в конце каждой статьи (кроме рецептов) автоматически выводится блок **«Свериться с Луной»** — текущие благоприятные даты и ссылка на календарь месяца. Отдельно ничего заполнять не нужно.

### Лунный календарь: проверка разметки (schema.org)

На странице календаря выводятся `ItemList` (дни месяца со ссылками-якорями), `FAQPage` (частые вопросы) и `BreadcrumbList`; на страницах категорий в крошках добавляется 4-й уровень.

**Быстрая локальная проверка (без интернета и входа):** в корне темы лежит скрипт `_tools/validate-schema.ps1` — он проходит по всем адресам из sitemap и проверяет код ответа, валидность JSON-LD и структуру разметки:

```
powershell -ExecutionPolicy Bypass -File _tools\validate-schema.ps1
powershell -ExecutionPolicy Bypass -File _tools\validate-schema.ps1 -Base https://ваш-домен
```

**Официальные сервисы (нужен публичный адрес — проверять после переноса на боевой домен):**
- Яндекс, валидатор микроразметки: https://webmaster.yandex.ru/tools/microtest/ (нужен вход в Яндекс ID; локальный адрес он не увидит).
- Google Rich Results Test (без входа, принимает и URL, и вставку кода): https://search.google.com/test/rich-results
- Валидатор schema.org (вставка кода): https://validator.schema.org/

Готовые образцы JSON-LD для вставки в валидаторы: `_tools/schema-sample-month.json`, `_tools/schema-sample-category.json`, `_tools/schema-sample-faq.json`. Вручную: открыть страницу → «Просмотр кода страницы» → найти `application/ld+json`.


**Ежегодный чек-лист (раз в год):**
1. Проверить фазы и знаки на новый год: открыть `/lunnyj-kalendar/` и сверить с публичным лунным календарём (±1 день).
2. Вычитать интро месяцев — актуализировать цифры и отсылки к статьям.
3. Проверить FAQ и schema во **валидаторе Яндекса**.
4. Обновить SEO/интро под новый год (блок выше).
5. В **Яндекс.Вебмастере** отправить страницы месяцев на переобход.
6. Пункт меню «Лунный календарь» → **уже добавлен** в **Основное меню** (шапка) и **Футер: инструменты**, ссылка на `/lunnyj-kalendar/`. При переносе сайта на другой домен проверьте, что пункт на месте (**Внешний вид → Меню**).

<a id="растения"></a>
## 4. Растения

**Где:** админка → **Растения → Добавить растение**.

1. **Заголовок** — название (например, «Гортензия метельчатая»).
2. Текст — описание, посадка, уход (можно воспользоваться паттерном **«Гайд по растению»**).
3. **Фото растения** (обложка): справа → **Изображение записи**.
4. **Раздел** и **Тип** (справа или в блоке «Раздел»/«Тип») — см. пункт 5.
5. Блок **«Параметры выращивания»**: свет, полив, кислотность pH (от/до), почва.
6. Блок **«Совместимость»**: хорошие соседи и плохие соседи (по одной культуре через запятую или с новой строки).
7. Опубликуйте.

**Где появится:** страница растения по адресу `http://sadznaniy.local/rasteniya/<адрес>/`. Параметры и соседи выводятся блоками по стилю макета.

**Список растений** (админка → Растения) показывает колонки **Раздел** (таксономия), **Свет** и **Полив**.

## 5. Разделы и типы растений

## 7. Что и как показывается на главной

Главная собирается автоматически из вашего контента — редактировать код не нужно:

| Блок главной | Источник | Как наполнить |
|---|---|---|
| «Популярное» (чипы) | Настройки темы | Внешний вид → Сад знаний |
| «Блог и советы» | 2 последние записи | Записи → Добавить запись |
| «Календарь работ» | 3 ближайших события | События → Добавить событие |

Если блок пуст (нет записей/событий) — он показывает подсказку, а не пустоту.

<a id="калькуляторы"></a>
## 8. Калькуляторы

**Где:** раздел `/kalkulyatory/` — хаб инструментов; каждый калькулятор — своя страница плюс шорткод для статей.

### Калькулятор полива — `[sz_calc_water]`

Страница: `/kalkulyator-poliva/`. Считает объём воды за один полив, интервал между поливами, недельный расход и переводит литры в лейки или в минуты капельного полива.

**Как работает у читателя:** выбирает, что поливает (грядки / теплица / газон / кустарники / деревья), количество, почву, погоду и регион — получает цифру и расшифровку «как получилась». Параметры расчёта передаются в адресе страницы, поэтому ссылкой можно поделиться; регион подставляется автоматически из выбора в календаре дачника. Без JavaScript инструмент тоже работает.

**Как править нормативы (без нейронки):** админка → **Внешний вид → Сад знаний → «Калькулятор полива»**. Меняются:
- норма за один полив (л на 1 м² или на одно растение);
- базовый интервал между поливами (дни);
- поправки на почву и погоду (множители объёма и интервала);
- поправки на регион (множитель интервала: у Юга меньше 1 — поливать чаще, у Дальнего Востока больше 1 — реже);
- бытовые мерки: объём лейки и расход капельного полива.

**Правило:** все нормативы помечены «ФАКТ-ПРОВЕРКА» — сверяйте с инструкциями и справочником `_design/seo/region-facts.md`.

**Шорткод:** `[sz_calc_water]` (можно вставить в статью или страницу; поддерживает атрибут `title` для заголовка инструмента).

### Калькулятор удобрений — `[sz_calc_fert]`

Страница: `/kalkulyator-udobreniy/`. Считает дозу по действующему веществу: цель подкормки + группа культур + удобрение + площадь → граммы на 1 м² и на всю грядку, а также перевод в столовые ложки, спичечные коробки и стаканы.

**Что показывает дополнительно:** чего не хватает выбранному удобрению (и чем добрать) и где будет перебор по элементу — это подсказка, какое удобрение выбрать под цель.

**Как править нормативы:** админка → **Внешний вид → Сад знаний → «Калькулятор удобрений»**:
- сколько действующего вещества (N, P, K) нужно на 1 м² для каждой цели;
- поправки по группам культур;
- проценты действующего вещества в удобрениях (берите с упаковки — у производителей цифры разные);
- бытовые мерки: ложка, спичечный коробок, стакан.

**Шорткод:** `[sz_calc_fert]` (атрибут `title` — заголовок инструмента).

### Калькулятор грунта и pH — `[sz_calc_ph]`

Страница: `/kalkulyator-grunta-i-ph/`. Считает, сколько извести (или доломитовой муки) либо коллоидной серы нужно, чтобы сдвинуть pH на выбранный уровень, и переводит дозу в стаканы и вёдра.

**Главное отличие от типовых калькуляторов:** инструмент берёт диапазоны pH из карточек растений базы знаний и делит их на три группы — «подходит сейчас», «подойдёт после коррекции», «не подходит». То есть отвечает не только «сколько сыпать», но и «что здесь вырастет».

**Как править нормативы:** админка → **Внешний вид → Сад знаний → «Калькулятор грунта и pH»**:
- сколько граммов раскислителя нужно на 1 м² на каждый 1,0 pH (по типам почвы);
- то же для подкислителя (коллоидная сера);
- бытовые мерки: стакан и ведро в граммах.

Диапазоны pH растений правятся в карточках раздела «Растения» (поля «pH от» и «pH до»).

**Шорткод:** `[sz_calc_ph]` (атрибут `title` — заголовок инструмента).

### Калькулятор посева семян — `[sz_calc_sow]`

Страница: `/kalkulyator-poseva/`. Считает сроки **назад** от даты высадки в грунт: она зависит от региона, а не от календаря. Показывает день посева, дату высадки, возраст рассады, дату возвратных заморозков и обратный отсчёт до посева, а также ссылки на календарь работ месяца и карточку культуры.

**Как править нормативы:** админка → **Внешний вид → Сад знаний → «Калькулятор посева семян»**:
- даты по регионам в формате ММ-ДД: заморозки до, холодостойкие в грунт, теплолюбивые в грунт;
- возраст рассады в днях по культурам (0 — сеют сразу в грунт);
- сдвиг срока в днях: опережение (+) или задержка (−) относительно общей даты региона.

Теплолюбивые культуры (томаты, огурцы) считаются от «тёплой» даты, остальные — от даты холодостойких.

**Шорткод:** `[sz_calc_sow]` (атрибут `title` — заголовок инструмента).

### Посадочные страницы видов работ — `/uhod/poliv/`, `/uhod/obrezka/` и т. д.

Каждому типу работ календаря (Посев, Посадка, Полив, Подкормка, Обрезка, Защита, Сбор, Подготовка) соответствует своя страница с человеческим адресом и уникальным текстом. Страница собирается автоматически: события, отнесённые в админке к этому типу, выводятся по месяцам с датами, регионами и подсказкой по погоде; частые вопросы и ссылки на инструменты добавляются кодом.

**Как править текст:** «События → Тип работы» → нужный тип → поле **«Описание»**. Это и есть вводный текст страницы — пишите живым языком, с цифрами и местными деталями, ограничений по объёму нет. Заголовок H1 задаётся кодом: `includes/helpers.php`, функция `sad_znaniy_work_type_h1()`.

**Цвет метки** хранится в мета-поле термина `_sz_color`, выводится точкой рядом с H1 и в плитках «Другие виды работ».

**Как добавить новый вид работ:** добавить ключ в `sad_znaniy_work_types()` и цвет в `sad_znaniy_work_type_colors()`, затем сохранить постоянные ссылки («Настройки → Постоянные ссылки» → «Сохранить»). Термин появится в админке, страница `/uhod/<ключ>/` заработает.

**Хаб `/uhod/`** — страница «Уход за садом: восемь видов работ по срокам» со ссылками на все разделы; правится как обычная страница.

**Важно:** сроки в посадочных страницах не дублируются — они берутся из событий календаря и настроек регионов. Правьте событие в одном месте («События»), и оно сразу появится на странице своего вида работ.

вводный абзац → фото → 3–4 раздела H2 (один — вопросный, «Почему …?») → список шагов → таблица (схема подкормок или сроки по регионам) → «Частые ошибки» → FAQ (3 вопроса H3) → «Что почитать дальше» (2 внутренние ссылки).

- 600–900 слов, конкретика (цифры, сроки, дозировки), без «воды» и англицизмов.

- Внутренние ссылки — на реальные URL сайта (например, `/rasteniya/tomat/`, `/razdel/ogorod/`).
- Alt у фото заполнять после загрузки картинки.

## Как публиковать склад статей

Склад из 30 статей создан как **черновики** (Записи → Черновики). Публикуйте их по тирам, а не подряд.

### Порядок публикации
1. **ТИР A — диагностика (№1–8)** — публиковать первыми: это самые востребованные запросы («почему не плодоносят огурцы», «желтеют листья томатов» и т.д.).
2. **ТИР B — сезонные гайды (№9–20)**.
3. **ТИР C — подборки и справочники (№21–30)**.

### Темп
- Публикуйте по **3–5 статей в неделю** (не пачкой): всплеск публикаций на молодом домене выглядит как ИИ-контент и рискует пессимизацией. Ограничитель темпа — ваша вычитка фактов.
- Перед публикацией вставьте **фото** (блок «Изображение», сейчас `src` пустой — стоит метка `<!-- TODO: фото -->`) и пропишите **alt**.
- Проверьте **внутренние ссылки**: после публикации всего склада все ссылки между статьями «оживут» — кликните по ним и убедитесь, что они ведут на существующие страницы.

### Привязка событий к регионам (обязательное правило)

- **«Все регионы»** ставьте только для работ с действительно универсальными сроками: защита (обработки по фенофазе), подготовка (перекопка, грядки, теплица), обрезка плодовых до сокодвижения, побелка, влагозарядковый полив.
- **Посев, посадка и сбор — всегда конкретные регионы.** Одни и те же работы на Юге идут на 1–1,5 месяца раньше, чем в Сибири: общая дата дезинформирует читателя, а региональные страницы месяцев начинают противоречить друг другу.
- Окна для моркови и картофеля — в справочнике `_design/seo/region-facts.md`, раздел 9. Там же — правило про огурцы (посев на рассаду 20–25 апреля).
- Если событие уже есть по регионам, не создавайте общее «все регионы» на ту же работу: получится дубль в списке календаря. Правильнее поправить даты у региональных событий.

### Проверка фактов (обязательно перед публикацией)
- Дозировки удобрений и сроки сверить с инструкцией препарата или авторитетным источником.
- Сомнительные цифры в текстах — на вычитку (правило: сомневаешься в дозе — проверь).

### После публикации
- Статья появится в «Блоге и советах» на главной и в своей рубрике (Огород / Сад / Цветы).
- SEO-заголовок и описание уже заполнены — правьте в блоке «SEO (заголовок и описание)» при необходимости.

<a id="программатик"></a>
## 12. Программатик-SEO (страницы из календаря)

**Где:** админка → **📊 SEO-Хаб → Программатик**.

### Для чего этот инструмент
Инструмент автоматически собирает SEO-страницы из данных календаря под низкочастотные запросы («когда сажать томат в Сибири», «работы в огороде в мае»). Вы **не пишете эти страницы вручную** — вы заполняете календарь событиями, а страницы генерируются сами. Цель: больше проиндексированных страниц с готовым ответом на конкретный запрос, без ручной работы над каждой.

Сайт сам собирает SEO-страницы из данных календаря по трём шаблонам:

- `/kalendar/{регион}/{месяц}/` — «Работы дачника: регион, месяц»;
- `/kogda-sazhat/{растение}/{регион}/` — «Когда сажать растение (регион)»;
- `/uhod/{растение}/{месяц}/` — «Уход за растением: месяц».

Страница **живёт** (открывается и попадает в `sitemap.xml`) только при трёх условиях одновременно:

1. **≥5 событий** по этому срезу (регион+месяц / растение+регион / растение+месяц);
2. **интро ≥2 предложений**;
3. стоит галочка **«Вкл.»**.

### Статусы в таблице
- **живая** (зелёная) — все три условия выполнены, страница в sitemap;
- **черновик** (оранжевая) — данные есть, но не включена или интро короткое;
- **пустая** (серая) — событий меньше 5 (страница физически не существует).

### Пошагово: включить страницу
1. Откройте **📊 SEO-Хаб → Программатик**.
2. Найдите нужную строку (по URL или фразе).
3. В столбце **«Интро»** впишите 2–3 предложения с региональной конкретикой (заморозки, прогрев почвы, световой день). Каждое предложение — факт/цифра/риск, не шаблон.
4. Поставьте галочку **«Вкл.»**.
5. Нажмите **«Сохранить»**.
6. Проверьте: страница открывается, в `http://sadznaniy.local/sitemap.xml` появилась ссылка.

### Пошагово: выключить / убрать из sitemap
1. Снимите галочку **«Вкл.»** в строке.
2. Нажмите **«Сохранить»** — страница пропадает из sitemap (по прямому URL — 404).

### Пошагово: править интро / SEO
- **Интро** — текст в таблице, редактируется в любой момент.
- **SEO title / description** — поля над URL в таблице. Пустые = автогенерация «Фраза — календарь и сроки | Сад знаний». Заполненные = ручное переопределение.

### Как добавить регион (страница по региону)
Страницы регионов **не создаются вручную** — они пересчитываются из событий календаря:

1. Добавьте **≥5 событий** для нужного региона и месяца (раздел 3 «События календаря»).
2. Откройте **Программатик** — нужная строка появится со статусом «черновик».
3. Впишите интро и включите (см. выше).

### Напоминания (ритм работы)
- **При добавлении событий месяца** пересчёт матрицы идёт сам (при сохранении события). Если строки нет — перезагрузите экран.
- **Раз в месяц** — просмотрите новые строки, впишите интро, включите.
- **Темп:** не больше **10 включённых страниц в неделю**.
- **Не публикуйте пустышки:** страница с <5 событий не откроется, даже если поставить галочку.

### Правила качества (жёстко)
- Страница существует только при **≥5 событиях** и **интро ≥2 предложений**.
- Запрещён шаблонный интро-подстановочник («{месяц} — важное время для {региона}» без фактов). Каждое интро — факт/цифра/риск.
- **Каннибализация:** если страница по смыслу дублирует существующую статью — не включайте её, поставьте пометку «НУЖНО РЕШЕНИЕ ВЛАДЕЛЬЦА».

## 13. SEO-Хаб (Ключи / Программатик / Индексация / Эффективность)

**Где:** админка → **📊 SEO-Хаб**. Вкладки: Ключи / Программатик / Индексация / Эффективность.

Хаб — рабочее место продвижения: семантика → включение страниц → контроль индексации → измерение эффективности. Внешних сервисов нет до переноса на хостинг (Этап 8).

### Вкладка «Ключи» (семантика)
1. wordstat.yandex.ru → введите фразу → «Скачать» → выберите **CSV** (XLSX не принимается).
2. Приложите файл или вставьте строки «фраза;показы» → **Импортировать**. Дубли по фразе обновляются.
3. Инструмент сам размечает фразы на программатик-страницы по правилам (месяц + регион + культура).
4. **Частота меньше 10 — «слабая»** (серая строка): такие страницы не спешите включать.
5. **«manual»** — правило не сработало или такой страницы ещё нет в матрице: добавьте события календаря или поправьте правило.
- Правила правятся прямо на экране: строки вида «слово1, слово2 > шаблон» (kalendar / kogda-sazhat / uhod).
- Экспорт: «Карта (Markdown)», «Карта (CSV)», «Ключи (CSV)».
- «Очистить список» удаляет все фразы — необратимо.
- **Статусы:** *живая* — есть включённая программатик-страница; *привязана* — программатик-страницы нет, но есть своя страница (календарь с фильтром месяца/региона или карточка растения); *слабая* — частота ниже порога; *manual* — ничего не нашлось, размечайте вручную.
- **Порог «слабой» частоты** правится здесь же (по умолчанию 10). Понижая порог, вы соглашаетесь публиковать низкочастотные страницы.


### Порядок публикации склада статей
- Очередь — по сезонной актуальности: сначала темы мая и июня, октябрь-ноябрь уходят в очередь на август.
- Перед публикацией партии проверяйте внутренние ссылки и факты (дозировки — по инструкции препарата).

### Правила включения программатик-страниц
- Включаются только страницы без пометки «НУЖНО РЕШЕНИЕ ВЛАДЕЛЬЦА» (каннибализация со статьёй — страницу не включаем).
- Срезы с 3–4 задачами не добиваем ради числа: если у месяца/региона объективно мало работ — страница не включается.
- Спорные дозировки в текстах событий помечаются ФАКТ-меткой для вычитки владельцем.
### Уникальность текстов (важно)
- Не копируйте абзацы из чужих статей и справочников: пересказывайте своими словами, меняйте структуру фразы и порядок пунктов.
- Каждое событие — факт, цифра или риск по делу (глубина, норма, температура, срок), без воды.
- Однотипные события для разных регионов не должны совпадать текстом: добавляйте местную привязку — сроки, погодные риски, особенности почвы.
- Перед публикацией партии сравните новые тексты с уже опубликованными (например, по выгрузке «Карта (Markdown)»).

### Вкладка «Программатик»
Как включать и править страницы — см. раздел 12.

### Вкладка «Индексация»
- Свои логи визитов ботов (YandexBot / Googlebot / YandexImages) к страницам программатика и календаря — без внешних сервисов.
- Коды подтверждения прав (Яндекс.Вебмастер, Google Search Console) вставляются здесь; метки сразу выводятся в <head>.
- Кнопки проверки связи и «внешний статус» станут активны после Этапа 8 (константа SZ_EXTERNAL_ON в wp-config.php).
- «Выполнить задачу сейчас» — ручной прогон суточной задачи, ниже журнал последних запусков.

### Вкладка «Эффективность»
- Визиты страниц программатика и календаря, клики «Подробнее → статья». Визиты администраторов не считаются, куки не используются.
- Тренд = последние 7 дней против предыдущих 7. «Позиция» заполнится после Этапа 8.

### Порядок работы (ритм)
- **Шаг 1. Сбор семантики** — Вордстат → CSV → импорт на «Ключах»: 30 мин/мес.
- **Шаг 2. Включение программатик-страниц** — не больше 10 в неделю: 10 мин/нед.
- **Шаг 3. Понедельничный ритуал** — «Эффективность» → ТОП-10 падающих; падение больше 30 % → открыть страницу, проверить интро и события месяца: 5–15 мин/нед.
- **Шаг 4. Месячный отчёт** — экспорт карты (Markdown/CSV), сверка с календарём: 30 мин/мес.
- **Шаг 5. После Этапа 8** — Метрика + Вебмастер + Google Search Console, включить SZ_EXTERNAL_ON, проверить синхронизацию на «Индексации».

> Фронтенд от хаба не страдает: аналитика невидима и не грузит страницы.

## 14. Дистрибуция: автопостинг в соцсети (Этап 8.5)

Раздел админки **«📢 Дистрибуция»** — пять вкладок: *Автопостинг / Настройки каналов / Партнёрки / Маркировка / Помощь*.

### Мастер-выключатель «СТАРТ»

Модуль **выключен по умолчанию** и ничего не публикует. Когда сайт уже на хостинге и каналы подключены, нажмите **«▶ СТАРТ автопостинга»** на вкладке «Автопостинг». С этого момента анонсируются только записи, вышедшие **после** нажатия (метка времени сохраняется) — статьи и растения, опубликованные раньше, не уйдут «пачкой». Рядом — «СТОП» (пауза, очередь сохраняется) и «Сдвинуть границу на сейчас».

### Как работает очередь

1. Публикация статьи или карточки растения (в том числе отложенная по расписанию) ставит задание в очередь.
2. Время отправки — ближайший слот **после даты публикации** (слоты по умолчанию 09:00 / 13:00 / 19:00). Несколько записей в один слот разводятся по времени.
3. WP-Cron каждые 5 минут берёт готовое задание: один пост за прогон, пауза между отправками не меньше 60 секунд, до 3 попыток.
4. Лимит — не больше 3 постов в день на сеть (настраивается). Если лимит исчерпан, задание переносится на следующий день.
5. Успех → статус «Опубликовано» + пометка сети в записи (повторно та же статья не постится). Ошибка → статус «Ошибка» с человеческим пояснением.

### Подключение Telegram за 5 минут

1. В Telegram откройте **@BotFather** → команда `/newbot` → задайте имя. Придёт токен вида `123456:AA...` — скопируйте.
2. Создайте канал (можно тестовый) и добавьте бота **администратором канала** с правом публикации.
3. Узнайте `chat_id`: перешлите любой пост канала боту **@userinfobot** либо укажите `@username` канала.
4. Вкладка **«Настройки каналов»** → Telegram: включите «Публиковать», вставьте токен и chat_id, сохраните.
5. В блоке **«Проверка связи»** нажмите «Проверить Telegram» — в канале появится тестовый пост.

### Подключение ВКонтакте (появится в Партии 3)

1. Сообщество → «Управление» → «Работа с API» → создайте ключ с правами `wall` и `photos`.
2. `owner_id` — числовой ID сообщества; для сообществ со знаком минус (например, `-12345678`).
3. Вставьте ключ и owner_id в «Настройки каналов».

### Почему пост не ушёл (три частые причины)

1. **Автопостинг выключен** — нажмите «СТАРТ» на вкладке «Автопостинг».
2. **Канал не включён или не задан токен** — проверьте галочку «Публиковать» и поля токена/chat_id, затем «Проверить связь».
3. **Запись вышла раньше границы старта** — в очереди нажмите «Отправить сейчас».

Отдельный случай: если в статье есть ссылка на чужой сайт, задание получает статус **«Требует проверки»** — уберите ссылку либо отправьте вручную (до настройки маркировки через ОРД такие посты не публикуются автоматически).

### Еженедельный ритуал (5 минут)

«📢 Дистрибуция» → «Автопостинг»: просмотрите статусы «Ошибка» и «Требует проверки», нажмите «Повторить» у исправимых, сверьте статистику за 30 дней по сетям.

## 15. Региональный контур: как это работает

Единый регион посетителя хранится в одном месте и используется всеми блоками сайта.

### Где хранится регион
- **`localStorage`, ключ `sz_region`** — значения `south` · `mid` · `ural` · `sib` · `dv`.
- **Cookie `sz_region`** (на год) — её читает сервер, поэтому блоки уже отрисованы под ваш регион (SSR).
- Модуль — `assets/js/region.js`. API: `window.szRegion.getRegion()`, `setRegion(key)`, `onChange(cb)`; событие `sz:region-change`.
- Старый ключ календаря (`sad_znaniy_cal.region`) переносится в `sz_region` автоматически при первом визите.

### Что реагирует на регион
| Блок | Как ведёт себя |
|---|---|
| Индикатор в шапке «📍 {регион} ▾» | выбор региона; ссылки-варианты работают и без JS |
| Виджет первого визита | один раз (ключ `sz_region_asked`); не показывается, если регион уже выбран |
| Календарь дачника (`/kalendar/`) | чипы и список задач перестраиваются без перезагрузки |
| Виджет «Календарь работ» на главной | показывает 3 ближайших события своего региона |
| Карточка растения, блок «Лунные дни для посадки» | сезонные окна культуры по региону; вне окна — «сезон закрыт» (REST `/wp-json/sad-znaniy/v1/plant-moon`) |
| Таблицы сроков в статьях и карточках | подсвечивается строка вашего региона или колонка с ним (`region-tables.js`) |

### Как добавить свой региональный блок
1. **Сервер (SSR):** возьмите регион из `sad_znaniy_current_region()` и отрисуйте блок под него; контейнеру дайте атрибут (например `data-sz-region-scope`).
2. **Клиент (без перезагрузки):** подпишитесь на изменение региона:
   ```js
   window.szRegion.onChange(function (region) { /* обновить блок */ });
   ```
   либо слушайте событие `document.addEventListener('sz:region-change', ...)`.
3. **Не создавайте своё хранилище** (localStorage/cookie) для региона — только `sz_region`.
4. Проверьте: смена региона в шапке обновляет блок без перезагрузки, а после перезагрузки блок отрисован сервером под тот же регион.

### Как добавить новый регион
1. `includes/helpers.php` → `sad_znaniy_region_keys()` (ключ + подпись) и `sad_znaniy_region_slugs()` (URL-слаг).
2. `includes/region.php` → `sad_znaniy_region_aliases()` — словоформы для поиска в таблицах (например «примор»).
3. Индикатор, виджет, календарь и подсветка таблиц подхватят регион автоматически. Для сезонных окон добавьте события календаря с этим регионом.

### Проверка (2 минуты)
1. Любая статья с таблицей сроков: выберите регион в шапке — строка (или колонка) подсветится без перезагрузки.
2. Карточка растения: блок «Лунные дни» покажет окно культуры либо «сезон закрыт — вернётся в {месяц}».
3. F12 → Application → Local Storage: `sz_region = sib`; Cookies: `sz_region = sib`.

## 16. Изображения: требования и подсказки в админке

Чтобы не забывать про размер, вес и alt, тема показывает подсказку прямо там, где вы вставляете картинку.

**Где смотреть:**
- **Редактор записи / растения / страницы** — панель **«📷 Изображения: требования и alt»** в правой колонке (вкладка «Запись»/«Страница», сразу под «Изображение записи»; открыта по умолчанию, можно свернуть).
- **Тот же редактор, низ экрана** — метабокс «Изображения: требования и подсказка alt» (полная версия с чек-листом).
- **Под полем «Изображение записи»** — короткая версия подсказки.
- **Внешний вид → Изображения: требования** — единый справочник: таблица размеров, правила alt/title, чек-лист и живой пример подсказки.

**Требования по местам:**

| Где | Формат | Размер | Вес |
|---|---|---|---|
| Карточка растения | JPEG / WebP | 1200×900 (4:3) | до 250 КБ |
| Обложка статьи | JPEG / WebP | 1600×1000 (16:10) | до 300 КБ |
| Страница | JPEG / WebP | 1600×900 (16:9) | до 300 КБ |
| Фото внутри текста | JPEG / WebP, схемы — PNG | 1200×800 (3:2) | до 200 КБ |
| Логотип (Настроить → Свойства сайта) | PNG, прозрачный фон | 400×120 | до 60 КБ |
| Иконка сайта / favicon | PNG / ICO | 512×512 (квадрат) | до 100 КБ |
| Картинка соцпоста (Telegram / VK / MAX) | JPEG | 1200×630 (1,91:1) | до 300 КБ |

**Правила alt и title:**
- **Alt — обязателен** и у миниатюры, и у каждого фото в тексте: 5–12 слов, ключевая фраза + что видно на снимке. Без alt фото не попадает в поиск по картинкам.
- **Title (атрибут) — не обязателен.** Google и Яндекс берут смысл из alt, подписи и окружающего текста; title показывается только как всплывающая подсказка при наведении. Заполнять его «для поисковиков» не нужно.
- **Имя файла** — латиницей через дефис с ключевой фразой: `krokus-posadka-i-uhod.jpg`.

Тема сама собирает подсказку alt для конкретного материала (заголовок + контекст типа записи) — строка показывается в подсказке, её можно скопировать кнопкой «Скопировать alt» и уточнить под снимок. Имя файла тоже предлагается автоматически (транслит из слага или заголовка).

Если при назначении «Изображения записи» у файла ещё пустой alt, тема заполняет его автоматически — останется проверить и уточнить в «Медиафайлы». Уже заполненный alt не перезаписывается.

## 17. Анонсы статей: откуда берётся отрывок

Анонс в карточках (например, на /stati/), на главной, в соцпостах и в поисковых сниппетах собирается по одной цепочке:

1. **Поле «Отрывок»** — если заполнено вручную (в блочном редакторе: правая колонка → «Отрывок»), берётся оно.
2. **SEO-описание** (`SEO (заголовок и описание)` → «SEO-описание») — если «Отрывок» пуст, анонсом становится SEO-описание. Оно уже написано у всех статей (120–160 знаков) и годится как готовая выжимка.
3. **Начало текста** — если нет и SEO-описания.

Поэтому заполнять «Отрывок» не обязательно: достаточно SEO-описания. Нужен особый анонс для конкретной статьи — заполните «Отрывок», он важнее.

Соцпосты (Telegram / VK / MAX) для текста поста используют тот же анонс: Telegram и MAX — до 3 предложений, VK и OK — до 200 знаков.

## 18. Картинка в карточках /stati/ и /rasteniya/

Карточки показывают миниатюру, даже если «Изображение записи» не задано:

1. Задана обложка («Изображение записи») — берётся она.
2. Обложки нет — берётся **первое изображение из текста материала** (блок «Изображение» с привязкой к медиатеке или первый `<img src="…">`). Заглушки «TODO: фото» без картинки пропускаются.
3. Картинок нет вообще — карточка выводится только текстом (как раньше).

В карточке фото показывается небольшим, слева от анонса (квадратный кроп 132 px; на узких экранах — 104 px). Alt берётся у самого изображения, а если он пуст — собирается из заголовка материала, поэтому картинка индексируется по теме.

Требования к самим файлам (размер, вес, формат) — в §16, анонс — в §17.
