## 3. Права файлов

Локально NTFS: POSIX-права не применяются, `fileperms()` отдаёт 0666 на все 734 объекта `wp-content`, `wp-config.php` — 0666. **Проверка прав на локалке бессмысленна, реальная проверка — только на хостинге.** Целевая модель и готовые команды `chmod` — в чек-листе переноса (S2, приложение В): каталоги 755, файлы 644, `wp-config.php` 600, `uploads` — запись только для владельца веб-сервера, `wp-content` без 777.

## 5. XML-RPC

`xmlrpc.php` присутствует; GET → 405, **POST `system.listMethods` → 200** (сервер отвечает, RPC включён). Jetpack и подобные плагины не используются — внешних потребителей XML-RPC у нас нет. Статус: 🔴 отключить (брут по `wp.getUsersBlogs`, pingback-абузы).

## 6. REST API и перечисление пользователей

- `/wp-json/wp/v2/users` → **200** и тело содержит `"name":"admin"`, `"slug":"admin"`, `"link":"…/author/admin/"`. То есть логин администратора виден **до всякого входа**.
- `/wp-json/wp/v2/users/1` → 200, то же.
- `/?author=1` → **301** → `/author/admin/` (200) — второй канал раскрытия логина.
- Статус: 🔴 закрыть список/одиночные users для неавторизованных и заглушить перечисление через `?author=N`.

## 8. Заголовки безопасности

Проверены ответы главной, `/wp-admin/`, REST. Есть только `X-Content-Type-Options: nosniff` (его отдаёт сам WP на REST). Отсутствуют: `X-Frame-Options`, `Referrer-Policy`, `Content-Security-Policy`, `Permissions-Policy`, `Strict-Transport-Security` (последний — только на боевом и только по HTTPS). `Server: nginx/1.26.1` — версия сервера раскрыта (на боевом `server_tokens off`). Статус: 🔴 добавить базовый набор в S2.

## 9. Ограничение попыток входа

Не реализовано: `wp-login.php` доступен, счётчика попыток, задержек и блокировок нет; «своего» модуля безопасности в теме нет. **Нет запросов вне домена и нет рендера аватаров: `get_avatar`/Gravatar в теме не используются (поиск по теме — 0 совпадений), значит внешних запросов оттуда не будет.** Статус: 🔴 сделать в S2 — таблица в БД (`ip`, `attempts`, `lock_until`), 5 неудачных попыток → блок 15 минут, журнал входов и блокировок, экран «🛡 Безопасность».

## 12. Что прошу утвердить (решения по S2)

1. **Логин `admin`:** создаю нового администратора с неочевидным логином (предлагаю `sz_owner`), перевожу на него авторство всех записей (сейчас весь контент на авторе #1), затем удаляю `admin`; display_name меняю с «admin» на «Редакция». Подтвердите логин или предложите свой.
2. **wp-config (правки согласовываю с вами — исключение из запрета):**
   - `define('DISALLOW_FILE_EDIT', true)`;
   - `FORCE_SSL_ADMIN` — по условию `if ('local' !== WP_ENVIRONMENT_TYPE)`, то есть «включится» на хостинге сам;
   - лог ошибок **вне webroot**: `ini_set('error_log', dirname(ABSPATH) . '/logs/php-error.log')` (локально папка `C:\Users\krs3d\Local Sites\sadznaniy\logs\`, на боевом — `../logs/`); `WP_DEBUG`/`WP_DEBUG_LOG` локально остаются `true`, на боевом — `false` тем же условием окружения;
   - `DISALLOW_FILE_MODS` — предлагаю включить **только** на боевом (на локалке мешает обновить ядро).
3. **Бэкапы вне webroot:** переношу `wp-content/backups/*.sql` в `C:\Users\krs3d\Local Sites\sadznaniy\backups\`, папку `wp-content/backups` удаляю; все будущие бэкапы (S3) — только туда.
4. **XML-RPC** — отключаю полностью (внешних веб-клиентов у нас нет).
5. **REST:** закрываю `/wp/v2/users` и `?author=N` для неавторизованных. Заголовок `<…/wp-json/>` предлагаю **оставить** (стандартный, не секрет) — скажите, если убрать.
6. **CSP:** предлагаю сразу рабочий, но только для **фронтенда** (админку не трогаем — Gutenberg): `default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; script-src 'self' 'unsafe-inline'; object-src 'none'; base-uri 'self'; frame-ancestors 'self'`. Inline необходим: WP и наши скрипты вставляют inline-данные. Проверю живьём на главной, статье, растении, календаре и калькуляторе.
7. **`wp-cron`:** на боевом `DISABLE_WP_CRON = true` + системный cron каждые 15 минут (панель), внешний доступ к `wp-cron.php` — только с localhost.

**Приёмка S1:** вы утверждаете пункты 1–7 (и, при необходимости, правите формулировки) → начинаю S2 «Лечение по аудиту» и по каждой строке таблицы ставлю «решено» с живой проверкой (`xmlrpc.php` → 403, REST users → 401/404, 6 неверных паролей подряд → блок 15 минут).

**Воспроизводимость:** проверки повторяемы — `curl.exe -s -o NUL -w '%{http_code}' <URL>`; аудит-скрипты и пробники — в `_tools/` (в S2 каждый получит CLI-guard, чтобы его нельзя было вызвать из браузера).
