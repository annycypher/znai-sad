**Нагрузка без кэша — главный риск этого трафика.** Сейчас в проекте нет страничного кэша (пункт «Кеш (тесты на LocalWP)» в PROJECT-PLAN ещё открыт), а 1 000–3 000 визитов в день — это 30–90 тыс. просмотров в месяц «живого» PHP. Поэтому до сезона включаем собственный статический кэш в теме (без плагинов и внешних сервисов) — это дешевле, чем тариф уровнем выше. Тяжёлые массовые операции (пересчёт ключей, пересборка матрицы, импорт Вордстата) делаем **только локально** и заливаем готовую базу.

## Деплой-процесс через `git remote`

Составлен 06.11.2026. Правило проекта: любое изменение кода идёт **локально → проверка локально → `git commit` → выгрузка → smoke-проверка**. Прямых правок на боевом нет, кроме конфиг-мелочей по согласованию (с бэкапом файла рядом).

### Реквизиты

| Что | Значение |
|---|---|
| Репозиторий (origin) | `git@github-znai-sad:annycypher/znai-sad.git` (он же `https://github.com/annycypher/znai-sad`) — доступ подтверждён 06.11.2026 |
| Локальный корень | `C:\Users\krs3d\Local Sites\sadznaniy\app\public` |
| Локальный предпросмотр | `http://sadznaniy.local/` |
| Боевой сервер (SSH) | `novidesiru@77.222.61.245`, webroot `/home/n/novidesiru/znai-sad/public_html` |
| Клон на сервере | `/home/n/novidesiru/znai-sad/_repo` (вне webroot, закрыт правилом 404) ⏳ создаётся при первом деплое через git |
| Ключ деплоя | Локальный ключ `~/.ssh/id_znai_sad` (ed25519, без пароля) + алиас `github-znai-sad` в `~/.ssh/config`; в GitHub → Settings → Deploy keys добавлен **с правом записи**. Проверено `git push` 06.11.2026: `1f87a5c..0470c54 main -> main`, `ahead=0` |

### Схема

```
локально: правка → php -l → демо на http://sadznaniy.local/ → git commit
        → git push origin main
сервер:  cd /home/n/novidesiru/znai-sad/_repo && git pull --ff-only
        → rsync -a --delete --exclude _design --exclude _docs --exclude _tools --exclude _templates \
             wp-content/themes/sad-znaniy/ /home/n/novidesiru/znai-sad/public_html/wp-content/themes/sad-znaniy/
```

Почему `rsync`, а не «сайт прямо из `_repo`»: webroot трогаем минимально — меняются только файлы темы; `uploads`, ядро и `wp-config.php` деплоем не затрагиваются. Исключения `_design/_docs/_tools/_templates` — папки разработки, им в web не место (они ещё и закрыты 404-правилом).

### Крон сайта на sweb (06.11.2026)

SSH `crontab` на хостинге недоступен (`/var/spool/cron` отсутствует, `crontab -l` → Permission denied) — задачи ставятся **только в панели sweb** (`cp.sweb.ru` → «Планировщик заданий»). Время панели — MSK (UTC+3).

| Что | Значение |
|---|---|
| Задача в панели | `znai-sad-wp-cron`, расписание `*/5 * * * *` (каждые 5 минут) |
| Команда | `/home/n/novidesiru/znai-sad-cron-driver.sh` |
| Драйвер | там же, `chmod 700`, sha256 `7950a419c085ecb4c63a66be88e2fa9ae2f8e898f5d83de4495db6ddaf767940` |
| Лог | `~/znai-sad-cron.log` (ротация: последние 2000 строк, внутри драйвера) |
| Маркер свежести | опция WP `sz_last_cron_run` (epoch, пишется только при `rc=0`) |

Правила установки:

- в поле команды панели — **только** путь к драйверу. Расписание в команду не писать: панель сама подставляет префикс `мин час день месяц день-недели`. Проверено 06.11.2026: команда, начинавшаяся с `*/5 * * * *`, дала `*/5: No such file or directory`, а расписание сохранилось как «в :05 каждого часа»;
- коммент-маркер (`#znai-sad-wp-cron`) панель дублирует в поле «комментарий» — второй раз в команду не добавлять;
- запуск по URL невозможен: `.htaccess` содержит `<Files "wp-cron.php"> Require local`, снаружи `https://znai-sad.ru/wp-cron.php` = **403** — только shell;
- PHP для крона — `/usr/bin/php8.3` (не `/usr/bin/php`: там 5.2.17 без ini).

Проверка (read-only):

```sh
tail -3 ~/znai-sad-cron.log          # строки с шагом 5 минут, все rc=0
/usr/bin/php8.3 ~/wp-cli.phar --path=~/znai-sad/public_html cron event list --fields=hook,next_run_relative
# ожидается: ни одного «now»/«ago»; sz_social_cron — до 5 минут
```

Управление задачей можно и через JSON-RPC панели (`/vh/cron`: `getTasks`, `addTask {minute,hour,day,month,weekday,command,comment}`, `removeTask {task}`) — вспомогательный клиент лежит в соседнем проекте: `calc_docs\sweb-migration\panel-api.ps1`.

**Кто за что отвечает.** Домен живёт у **регистратора**, сайт — на **хостинге**; между собой они связаны DNS-записями. Пока домен не делегирован, ни один A/CNAME не подействует.

**Где смотреть NS-серверы (делегирование):**
- В панели регистратора: карточка домена → «DNS-серверы» / «NS-серверы» / «Делегирование».
- Публично, без панели: `whois.tcinet.ru` (whois для `.ru`) или веб-сервисы `nic.ru/whois`, `reg.ru/whois`, `2ip.ru/whois`. Строки `nserver:` в ответе — это и есть NS.
- Если там серверы хостинга (например `ns1.timeweb.ru`, `ns2.timeweb.ru`) — записи правим **в панели хостинга** («Домены → DNS-записи»). Если NS регистратора — записи правим **в панели регистратора**. Правило: **где NS — там и записи**.

**Минимальный набор записей:**

| Тип | Имя (Host) | Значение | TTL | Зачем |
|---|---|---|---|---|
| A | `@` (в некоторых панелях — пусто) | IP сайта, например `185.х.х.х` — точное значение дам после покупки | 3600 | сайт без www |
| A или CNAME | `www` | тот же IP (**A**) либо `znai-sad.ru.` (**CNAME**) | 3600 | сайт с www |
| TXT | `@` | строка подтверждения Яндекса/Google — по желанию, вместо meta-тега | 3600 | права на сайт без правки файлов |
| CNAME | `mail` / `smtp` | значения из почтовой панели (по желанию) | 3600 | почта на домене |
| TXT | `@` | `v=spf1 ...` (по желанию) | 3600 | защита почты от подделок |

**Тонкости, на которых спотыкаются:**
- `@` = сам домен; в части панелей вместо `@` поле оставляют пустым.
- Точка на конце (`znai-sad.ru.`) означает «абсолютное имя» — не добавляйте её руками, если панель делает это сама.
- TTL 3600 с (1 час) — норма; **перед переездом** снижают до 300 с, чтобы изменения разошлись быстро.
- Нельзя держать одновременно `A www` и `CNAME www`. `AAAA` (IPv6) — только если хостинг выдал IPv6-адрес.
- Не трогайте существующие `MX`/`TXT`: на них может стоять ваша почта. Wildcard `*` не создавать.
- Проверка после сохранения: `nslookup znai-sad.ru` или `ping znai-sad.ru`; «обновление 3–24 часа» — это TTL плюс кэши провайдеров.

**Порядок (после покупки хостинга):** 1) регистратор → домен → NS = серверы хостинга (либо сразу правим DNS в панели хостинга); 2) панель хостинга → «Домены → DNS» → A для `@` и `www` → IP сайта (пришлите мне точное значение); 3) ждать 3–24 ч; 4) проверить `nslookup`/whois; 5) сказать мне — включаю SSL, делаю `search-replace` на боевой адрес, правлю sitemap/robots/canonical.

- Секреты — только защищённым сообщением. `wp-config.php`, `*.sql`, `*.zip` в репозиторий не попадают (`.gitignore`).
- SSL Let’s Encrypt продлевается автоматически; раз в 3 месяца проверять срок.
- РСЯ — не подключаем до стабильного трафика (правило плана).
- Дистрибуция (Telegram/ВК, партии 2–3) — после 8.4.

## Что нужно от вас (сводка)

1. Хостинг Timeweb «Optimo» 437 ₽/мес (или другой тариф по вашему выбору) + домен `.ru` в подарок — есть 10 дней бесплатного теста. **Покупка отложена:** сначала полностью готовим сайт и безопасность.
2. Доступы к хостингу — защищённым сообщением (SFTP/SSH + панель).
3. DNS-записи — по моей инструкции после покупки.
4. Регистрация в Яндекс.Вебмастере, Метрике, Google Search Console — инструкции пришлю пошагово.
5. Приватный git-репозиторий + URL (для партии 8.4).
